# 0012. 범위: 모델 입출력 v3 의존 기능은 꺼짐, 재질문 단계는 만들지 않는다

## 상태
승인(2026-11-10, 영역 작업자 판단)

## 맥락
계약은 v3 의존 기능 셋(확인 중 상태, 뜻 묻기 한도 면제, 설명 3회 뒤 직원 도움)을 활성 모델 패키지의 model_io_version 이 v3 이상일 때만 켜라고 정한다. ActionExtractionRules 의 설명은 '문진 끝에 한도로 비운 문항을 다시 묻는 재질문 단계'도 언급한다.

## 결정
서비스는 계약의 ModelIoVersion 에 v2 만 있어 v3 기능을 켜지 않는다(시작 때 모델 상태에서 읽은 버전을 세션에 남긴다). 되묻기 한도는 REASK·CONFIRM 의 연속으로 세어 서비스가 문항을 건너뛴다. 모델 상태(model_io_version)는 model-runtime 의 getModelStatus 에서 읽고 30초 동안 캐시한다(활성화 때만 바뀌므로 턴마다 읽지 않는다. 30초는 측정하지 않은 선택이다). 재질문 단계는 브리프와 flow-resolutions 가 정한 흐름('한도에 닿으면 건너뛴다')에 없어 만들지 않았다.

## 왜
브리프와 docs/v7-flow-resolutions.md 가 정본이다. v3 모델이 없어 켜는 경로를 시험할 수 없으므로 만들면 확인하지 못한 코드가 된다.

## 검토한 대안과 버리는 이유
- v3 경로를 미리 구현: 계약의 v3 값(분류, 상태)이 없어 만들 수 없다.

## 결과
얻는 것: 확인한 범위만 구현한다. 감수하는 것: v3 가 활성이 되면 이 영역의 session·turn 을 고쳐야 한다. 재질문 단계는 변경 요청 survey-service-007 로 확인을 요청했다.

## 되돌리는 조건
계약이 v3 값과 재질문 단계를 정하면 새 ADR 로 구현한다.
