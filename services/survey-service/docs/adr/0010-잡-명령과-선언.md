# 0010. 잡(DETECT_FAILURES, PURGE_EXPIRED): 명령 모양, 시각 주입, 선언 파일

## 상태
승인(2026-11-10, 영역 작업자 판단)

## 맥락
design.md 4절 JobName 은 DETECT_FAILURES 와 PURGE_EXPIRED 를 이 영역의 잡으로 정한다. 잡은 입력(JobRunInput)을 인자로 받고 JobRunResult 한 줄과 종료 코드 0·75·1 로 답한다(D130).

## 결정
`python -m survey_service.jobs <잡 이름> --requested-at <RFC 3339>` 로 한 번 실행한다. 잡은 시계를 읽지 않고 요청한 시각을 쓴다. DETECT_FAILURES 는 아직 보지 않은 턴 기록을 읽어 규칙 둘(추출 출력 불가로 실패, 되묻기 한도로 건너뜀)에 맞는 사례를 만들고 본 턴을 표시한다. PURGE_EXPIRED 는 유휴 60초를 넘긴 세션을 EXPIRED 로 바꾸고, 180일 지난 발화 원문과 만료 하루 뒤의 쓰지 않은 시작 코드와 실패 시도를 지운다. DB 가 안 닿으면 75, 그 밖의 실패는 1 이다. 선언은 `jobs.json`(시간 상한 600초는 jobs 템플릿 예시와 같은 값이고 측정이 아니다)에 둔다.

## 왜
D39(같은 입력이면 같은 결과, 여러 번 실행해도 안전), D130·D131. 180일은 계약 RawUtteranceRetentionDays(L12). 시험이 두 번 실행해도 결과가 같은지 본다.

## 검토한 대안과 버리는 이유
- 앱 안의 백그라운드 스케줄러: 영역이 스스로 다른 일정을 가진다(일정은 deploy 의 몫, D131).
- 요청 처리 중 지우기: 환자 응답 시간에 영향.

## 결과
얻는 것: 일정과 분리, 멱등. 감수하는 것: 서비스 이미지의 잡 선언 라벨(io.openit.jobs)과 deploy 의 실행 경로는 서비스 틀에 없어 변경 요청 survey-service-005 로 남겼다.

## 되돌리는 조건
deploy 가 서비스 이미지의 잡 호출 모양을 정하면 따른다.
