# 0005. 웹 푸시(RFC 8030·8291·8292)는 라이브러리 없이 cryptography 와 PyJWT 로 조립한다

## 상태
승인(2026-11-10, 영역 작업자 판단)

## 맥락
직원·의사 알림은 표준 Web Push 로 보낸다(C11). 흔한 Python 라이브러리(pywebpush, py-vapid, http-ece)는 MPL-2.0 이다.

## 결정
RFC 8291 의 aes128gcm 암호화와 RFC 8292 의 VAPID(ES256 JWT)를 `link/push.py` 에서 조립한다. 암호 연산은 cryptography(Apache-2.0 또는 BSD), JWT 서명은 PyJWT(MIT)가 한다. RFC 8291 부록 A 의 시험 벡터와 받는 쪽 절차로 푼 결과를 시험한다. 푸시 서비스가 404·410 으로 답한 구독은 지운다(RFC 8030 7.3). 푸시는 최선 전달이고 실패해도 알림은 DB 와 스트림에 있다.

## 왜
ADR 0001·0017: 배포물 의존은 허용형만이다(MPL-2.0 은 파일 단위 복사 의무가 있다). 표준이 짧고(암호화 약 40줄) 시험 벡터가 RFC 에 있어 직접 조립의 위험이 작다. 값(TTL 1시간, VAPID 수명 12시간, 전송 제한 10초)은 RFC 8030 5.2·8292 2(24시간 이내) 안에서 고른 것이고 측정하지 않았다.

## 검토한 대안과 버리는 이유
- pywebpush: MPL-2.0 의존이 이미지에 들어간다.
- 외부 푸시 게이트웨이: 영역 밖 호출이 늘고 구성 요소가 는다.

## 결과
얻는 것: 허용형 라이선스만 유지한다. 감수하는 것: 암호 코드를 우리가 유지한다(시험 벡터가 회귀를 막는다). 실제 브라우저 푸시 서비스와의 연동은 이 환경에서 확인하지 못했다.

## 되돌리는 조건
허용형 라이선스의 표준 라이브러리가 나오면 그것으로 바꾼다.
