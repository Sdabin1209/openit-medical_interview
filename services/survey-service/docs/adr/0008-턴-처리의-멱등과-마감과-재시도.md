# 0008. 턴 처리: 같은 turn_id 멱등, 처리 중 표시, 재시도 1회, 마감 50초, 낙관적 반영

## 상태
승인(2026-11-10, 영역 작업자 판단)

## 맥락
같은 턴 재전송에 같은 결과를, 동시 요청에는 409 TURN_IN_PROGRESS 를 줘야 하고(D75), 실패한 턴은 세션 상태를 바꾸지 않는다. 모델 호출은 느리다.

## 결정
턴을 시작할 때 (세션, turn_id) 기록을 PROCESSING 으로 커밋한다. 이미 DONE 이면 저장한 응답을 그대로 준다. PROCESSING 이면 409 이다(마감 50초보다 오래 멈춘 PROCESSING 은 다시 시작한다). FAILED 는 다시 시작한다. 모델 호출 동안 세션 행 잠금을 쥐지 않고, 반영할 때 세션의 마지막 활동 시각이 그대로인지 확인하고 아니면 결과를 버리고 409 SESSION_NOT_ACTIVE 를 준다. 추출·응답은 출력 불가면 같은 요청을 1번 다시 보내고(시간 초과는 다시 보내지 않는다) 그래도 안 되면 200 에 실패 신호를 준다. 턴 전체 마감은 계약 SurveyTurnLimitSeconds(50초)다. 되묻기 한도로 건너뛸 때는 모델 응답을 부르지 않고 고정 문장과 다음 질문을 준다.

## 왜
계약 submitTurn 설명과 D75(1). 50초·21초·26초는 계약 TimeBudgetTable 값이다(측정이 아니라 판정 상한, D125). 모델을 부르는 동안 행 잠금을 쥐면 같은 세션의 상태 읽기(2초마다)와 직원 개입이 막힌다.

## 검토한 대안과 버리는 이유
- 행 잠금을 끝까지 쥐기: 직원 개입과 상태 읽기가 최대 50초 막힌다.
- 재시도 없이 바로 실패: 일시적 출력 불가에 환자가 같은 말을 다시 해야 한다.

## 결과
얻는 것: 멱등, 동시성, 안전(위험 정지가 진행 중인 턴을 이긴다). 감수하는 것: 낙관적 확인에 걸리면 환자가 그 턴을 다시 해야 한다.

## 되돌리는 조건
측정에서 턴 중복·충돌이 잦으면 세션 단위 직렬화(큐)를 검토한다.
