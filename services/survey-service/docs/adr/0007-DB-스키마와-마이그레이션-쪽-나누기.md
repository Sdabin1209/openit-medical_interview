# 0007. DB 스키마: JSONB 칸, 키셋 쪽 나누기, 앱 시작 때 마이그레이션(권고 잠금)

## 상태
승인(2026-11-10, 영역 작업자 판단)

## 맥락
영역 전용 PostgreSQL 16 에 세션, 턴 기록(trace), 알림, 실패 사례, 문항 세트를 저장한다. 계약 값은 JSON 이고 칸마다 조회하지 않는다.

## 결정
문항 세트 내용, 칸 값 표, 추출 출력은 JSON 칸(PostgreSQL 은 JSONB, 시험의 SQLite 는 JSON)에 둔다. 목록은 (시각, 식별자) 내림차순 키셋 커서로 나눈다(`limit` 기본 30 최대 100, 계약 PageLimit). 커서는 불투명한 base64url 문자열이다. 마이그레이션은 앱 시작 때 `alembic upgrade head` 를 PostgreSQL 권고 잠금(`pg_advisory_xact_lock`) 아래에서 돌린다. 시작 코드·세션·알림·턴은 모두 한 번 만든 뒤 상태 칸만 바꾼다.

## 왜
JSONB 는 PostgreSQL 이 JSON 의 표준 저장 형식이다. 키셋 쪽 나누기는 쪽 사이에 새 항목이 들어와도 중복·누락이 없다(오프셋은 있다). 시작 때 마이그레이션은 영역 DB 의 스키마를 영역이 소유하기 때문이고, 권고 잠금은 복제본이 동시에 시작해도 한 번만 돌게 한다.

## 검토한 대안과 버리는 이유
- 칸마다 정규화한 표: 계약 값이 바뀔 때마다 마이그레이션이 필요하고 조회 이득이 없다.
- 오프셋 쪽 나누기: 중복·누락.
- 별도 마이그레이션 잡: 영역이 스스로 서야 한다(이미지는 스스로 서는 단위).

## 결과
얻는 것: 계약 값 변경에 DB 가 둔감하다. 감수하는 것: JSON 안을 SQL 로 조회하기 어렵다. 시작이 마이그레이션만큼 늦다(측정하지 않았다).

## 되돌리는 조건
JSON 안의 값으로 조회·집계가 필요해지면 해당 칸을 별도 열로 올리는 마이그레이션을 더한다.
