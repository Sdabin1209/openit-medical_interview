# 0015. TLS 는 영역 게이트웨이가 끝내고 서비스는 평문 HTTP 로 듣는다

## 상태
승인(2026-11-11, 영역 작업자 판단, 계약 9.0.0 반영, 변경 요청 survey-service-006 의 답).

## 맥락
계약 `SurveyServiceEnv` 는 TLS 인증서·개인키 입력을 받았으나 서비스 틀은 평문 HTTP 였고 어느 쪽이 맞는지 계약에 없었다. 계약 9.0.0 은 정했다: TLS 는 영역 게이트웨이(Caddy)가 끝내고 클라이언트 인증서를 검증한다. 서비스 컨테이너는 영역 전용 내부 네트워크에서 평문 HTTP 로 `OPENIT_LISTEN_PORT` 를 듣고 게이트웨이만 닿는다. `OPENIT_TLS_CERTIFICATE_FILE`·`OPENIT_TLS_PRIVATE_KEY_FILE` 은 서비스가 이웃을 부를 때 보이는 클라이언트 인증서와 개인키이며 게이트웨이의 인증서 에이전트가 발급·갱신한다.

## 결정
1. 서비스는 TLS 를 끝내지 않는다. `python -m survey_service` 는 평문 HTTP 로 듣고 `Dockerfile` 의 `EXPOSE`·`HEALTHCHECK`·스모크 시험도 평문 HTTP 다.
2. `link_model_client` 는 model-runtime 을 부를 때 영역 게이트웨이의 CONNECT 터널(`OPENIT_EGRESS_PROXY`) 위 TLS 에서 루트 인증서(`OPENIT_ROOT_CERTIFICATE_FILE`)로 서버를 검증하고 클라이언트 인증서로 mTLS 를 한다(`link/tls.py ClientTls`).
3. 인증서 에이전트가 파일을 덮어쓰면 따른다: 요청 전에 인증서·키 파일의 수정 시각을 보고 바뀌었으면 같은 `ssl.SSLContext` 에 `load_cert_chain` 을 다시 부른다. 새 연결부터 새 인증서를 쓴다. 읽지 못하거나(에이전트가 쓰는 중) 짝이 맞지 않으면 앞의 상태를 두고 다음 요청에서 다시 본다.
4. `X-Forwarded-Client-Cert` 를 믿는 근거는 '서비스에는 영역 게이트웨이만 닿는다'는 영역 네트워크 구성이다. 게이트웨이는 클라이언트 인증서를 검증하고 입구(SAN gateway)의 인증서로 온 요청에서만 헤더를 넘기며 그 밖의 요청에서는 지운다(계약 `device_mtls`). 서비스는 헤더의 출처를 따로 확인하지 않는다. 이 근거는 `link/auth.py` 의 머리 주석에도 적었다.

## 왜
- 계약 9.0.0 `device_mtls`·`area_mtls`·`SurveyServiceEnv` 설명이 정본이다(TLS 종단을 한 곳에 두면 인증서 발급·갱신·검증 설정이 게이트웨이 하나에 모인다).
- 같은 컨텍스트에 다시 올리는 방식은 `SSLContext.load_cert_chain` 을 여러 번 불러도 된다는 표준 라이브러리 동작에 기댄다. 컨텍스트를 바꿔 끼우려면 httpx 클라이언트를 새로 만들고 요청 중인 낡은 클라이언트를 안전하게 닫는 일이 따라온다. 서버는 핸드셰이크에서만 클라이언트 인증서를 검사하므로 이미 열린 연결이 낡은 인증서로 남아도 갱신 주기(만료보다 한참 앞) 안에서는 문제가 없다. 시험이 실제 TLS 핸드셰이크(클라이언트 인증서 필수 서버)로 바뀐 인증서가 쓰이는지 본다.
- 수정 시각 비교는 요청마다 stat 두 번이라 비용이 작고 타이머·파일 감시 의존이 없다. 측정하지 않은 선택이다.

## 검토한 대안과 버리는 이유
- 서비스가 TLS 를 끝내기: 서비스마다 서버 인증서 갱신과 클라이언트 인증서 검증을 만들어야 하고 계약이 정한 방향이 아니다.
- 시간 간격 타이머로 다시 읽기: 간격 값을 정해야 하고 측정 근거가 없다. 파일이 바뀐 것을 직접 보는 쪽이 값이 필요 없다.
- inotify 같은 파일 감시: 컨테이너 마운트(읽기 전용, 파일 교체)에서 이벤트가 안 오는 경우가 있고 의존이 는다.
- 헤더 출처를 서비스가 확인하기(클라이언트 인증서 검증): 평문 HTTP 에서는 확인할 재료가 없다.

## 결과
얻는 것: 서비스 이미지는 TLS 설정이 없고 `/healthz` 가 평문으로 닿는다. 감수하는 것: 서비스가 게이트웨이 밖에서 닿을 수 있게 배포하면 누구나 기기 헤더를 위조할 수 있다(배포가 영역 네트워크를 지켜야 한다). 게이트웨이와 인증서 에이전트는 이 환경에서 만나지 못했다(시험은 로컬 TLS 서버).

## 되돌리는 조건
계약이 서비스 TLS 로 바꾸거나 헤더 출처를 서비스가 확인하게 정하면 새 ADR 로 바꾼다.
