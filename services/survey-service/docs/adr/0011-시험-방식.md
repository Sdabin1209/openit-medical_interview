# 0011. 시험 방식: 가짜 model-runtime, SQLite 와 PostgreSQL 16 에서 같은 시험, 인증을 붙인 계약 적합성 시험

## 상태
승인(2026-11-10, 영역 작업자 판단)

## 맥락
영역은 이웃 없이 혼자 시험해야 한다(D22). 계약 적합성은 Schemathesis 로 본다(ADR 0020). 인증이 있는 작업은 인증 없이는 401 만 만난다.

## 결정
model-runtime 은 계약 타입으로 만든 가짜(정해진 출력, 출력 불가, 시간 초과)다. 저장소는 실제 SQLAlchemy 구현을 임시 SQLite(기본)와 PostgreSQL 16 컨테이너(`pytest -m postgres`)에서 같은 시험으로 돈다. Schemathesis 는 작업의 security 요구에 맞는 신원(기기 헤더, 서명한 시험 토큰, 기계 토큰)을 붙이고, 빈 DB 와 실제 값을 심은 DB 둘에서 돈다. 시험은 hypothesis 로 입력만 만들고 호출은 우리 ASGI 클라이언트로 한다(DB 엔진이 한 이벤트 루프에 묶이므로). 스트림 작업은 끝나지 않아 뺀다. 예시 수 25 는 ADR 0020 의 임의 값이다.

## 왜
표준 도구로 계약대로 응답하는지 본다(ADR 0020). 시험이 429 의 Retry-After 가 계약 상한을 넘는 실제 결함을 잡았다. 제품 구성에 시험용 문(포트, 플래그)을 두지 않고 앱 팩토리에 의존을 주입한다(D123).

## 검토한 대안과 버리는 이유
- DB 를 가짜로: 실제 SQL 과 마이그레이션을 못 본다.
- PostgreSQL 만: 느려서 개발 반복이 느리다.

## 결과
얻는 것: 빠른 반복과 실제 DB 확인. 감수하는 것: 두 DB 에서 같은 코드가 돌도록 JSON·UUID·시각 형을 일반형으로 쓴다(UtcDateTime).

## 되돌리는 조건
SQLite 와 PostgreSQL 의 동작이 갈라지는 기능이 필요해지면 PostgreSQL 만 쓴다.
