# 0019. 연속 턴 실패 수는 세션 행의 실패 turn_id 목록에 두고, 세션 행 잠금 안에서 더하고 판정한다

## 상태
승인(2026-11-11, 영역 작업자 판단). 계약 9.3.0 `TurnFailureLimit` 을 구현한다. [0008](0008-턴-처리의-멱등과-마감과-재시도.md)의 "실패한 턴은 세션 상태를 바꾸지 않는다"를 좁힌다(바뀌는 것은 이 목록 하나).

## 맥락
환자 턴이 계속 실패하면 같은 안내가 끝없이 되풀이된다. 계약 `TurnFailureLimit`(3)은 세션마다 연속 실패 수를 세고 한도에 닿는 턴이 지금 문항을 건너뛰게 한다. 규칙은 계약이 정한다: 실패한 서로 다른 turn_id 마다 1 을 더하고, 같은 turn_id 의 재전송은 다시 세지 않으며, 턴이 기록될 때와 직원이 정지를 풀 때 0 이 되고, 더함과 판정은 한 번에 일어나 겹친 턴이 문항을 두 번 건너뛰지 않는다. 실패한 턴은 같은 turn_id 로 다시 처리될 수 있으므로(0008) 재전송은 실제로 일어난다.

## 결정
1. `survey_session.failed_turn_ids`(JSON 목록, 마이그레이션 0003, 기존 행은 빈 목록)에 연속으로 실패한 서로 다른 turn_id 를 둔다. 연속 실패 수는 그 길이다. 0 으로 되돌리는 일은 목록을 비우는 것이다(턴 기록, 정지 풀기).
2. 한도 값은 `session.TURN_FAILURE_LIMIT = 3` 상수다. 계약이 설치마다 바꾸지 않는다고 정해 환경 변수·설정으로 받지 않는다. 시험이 계약의 const 와 같은지 본다.
3. 더함과 판정은 턴의 결과를 반영하는 트랜잭션(세션 행을 `FOR UPDATE` 로 잠근 뒤)에서 읽은 최신 목록에 한다. 한 번의 더함이 한도에 닿으면 그 트랜잭션 안에서 건너뛰기까지 하고 목록을 비운다.
4. 한도에 닿은 턴은 `outcome=DONE` 으로 기록한다(같은 turn_id 의 재전송은 저장한 응답을 받는다). `failure_signal` 은 그 실패의 신호로 남기고 `reask_limit_hit` 은 아니다. 실패 사례 탐지는 `DONE` 이어도 `failure_signal=EXTRACTION_UNAVAILABLE` 이면 추출 실패 사례로 센다.
5. SQLite(개발·시험)는 `FOR UPDATE` 가 없고 읽기가 잠기지 않아, 세션 잠금 읽기(`get_session(for_update=True)`)가 같은 값을 다시 써서 쓰기 잠금을 먼저 잡는다. 운영 DB(PostgreSQL)와 같은 약속을 개발 DB 도 지키게 한다.

## 왜
- 목록이 단순한 횟수보다 맞다: A 실패, B 실패, A 재전송 실패에서 마지막 실패 turn_id 하나만 두면 A 를 새 실패로 센다. 계약 1항("서로 다른 turn_id 마다")을 정확히 지키려면 센 turn_id 들을 알아야 한다. 한도가 3 이고 3 에 닿으면 비우므로 목록은 최대 2 개다(행 크기 영향 없음).
- 세션 행 잠금 안에서 더한다: 이 서비스는 이미 결과 반영 트랜잭션에서 세션 행을 잠그고 있고(0008), 같은 행을 잠그는 PostgreSQL 의 `SELECT ... FOR UPDATE`(행 수준 잠금, 뒤 트랜잭션은 앞이 끝난 뒤의 값을 읽는다)는 읽고-더하고-쓰는 일을 직렬화한다. 계약 3항이 요구한 원자성이다.
- 건너뛴 턴을 기록(DONE)한다: 계약 4항이 "그 턴은 기록되어 같은 turn_id 의 재전송은 같은 결과를 받는다"고 정했고, 0008 의 재생은 DONE 기록의 저장한 응답을 준다.
- 값 3 은 사용자가 예로 든 값이고 측정하지 않았다(계약 `x-basis`).

## 검토한 대안과 버리는 이유
- 횟수 칸 + 마지막 실패 turn_id 칸: A, B, A 를 잘못 센다. 칸이 둘이고 같은 사실을 둘로 쪼갠다.
- 횟수 칸만: 같은 turn_id 의 재전송을 다시 센다(계약 1항 위반).
- 조건부 UPDATE(`WHERE failed_turn_ids = :읽은값`)와 재시도: 같은 효과이나 충돌 때 다시 읽어 시도하는 반복이 필요하고, 이미 있는 행 잠금으로 충분하다.
- 별도 표(세션, turn_id): 연속 실패 수는 세션의 상태이고 항상 최대 2 개라서 표를 더할 이유가 없다.
- 건너뛴 턴을 FAILED 로 기록: 재전송이 다시 처리되어(0008) 같은 결과를 받지 못한다.

## 결과
얻는 것: 겹친 턴이 문항을 두 번 건너뛰지 않는다(시험: 수가 2 일 때 실패하는 두 턴을 겹쳐 SQLite 와 PostgreSQL 에서 하나만 건너뜀). 재전송이 수를 늘리지 않는다. 감수하는 것: 세션 행에 칸 하나가 늘고 마이그레이션 0003 이 필요하다. 겹친 두 번째 실패 턴은 이미 옮겨 간 새 문항 기준으로 1 부터 센다. SQLite 의 잠금 읽기는 쓰기를 먼저 해서 같은 세션의 잠금 읽기끼리 직렬이 된다(개발·시험 DB 에서만).

## 되돌리는 조건
계약이 한도나 세는 단위를 바꾸면(예: 시간 창) 이 ADR 을 대체한다. 세션 행 잠금이 병목으로 측정되면 조건부 UPDATE 로 바꾸는 것을 검토한다(측정하지 않았다).
