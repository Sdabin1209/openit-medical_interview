# 0006. 계약 9.0.0 이 영역에 넘긴 입력: 엔진 주소, 이름 표, 레지스트리 자격, 클라이언트 인증서, 어댑터 배치

## 상태
승인(2026-11-11, model-runtime 영역 작업자). 변경 요청 model-runtime-003 의 1~5번에 대한 헤드 결정(계약 9.0.0)을 영역에 맞춘다. [ADR 0003](0003-레지스트리-패키지-형식-HTTP-클라이언트-TLS.md) 의 2항·3항을 확인하고 보강한다.

## 맥락
8.0.0 에서는 엔진 주소가 영역 안 고정 상수였고, 이름 표는 받기만 했고, 자격 파일과 가중치 형식은 임시 선택이었다. 9.0.0 이 각각을 입력·규칙으로 정했다.

## 결정
1. **엔진 주소는 `OPENIT_INFERENCE_ENGINE_URL`** 을 읽는다(계약 `InferenceEngineUrl`, http·https). 코드의 고정 상수를 없앴다.
2. **어댑터 배치 규칙.** 패키지의 어댑터 폴더는 `<OPENIT_MODEL_CACHE_DIR>/model-runtime/packages/<digest 16진수>/adapters/<역할>` 에 푼다. vLLM 의 `lora_path` 는 엔진 컨테이너가 보는 경로이므로, **엔진 컨테이너는 이 영역의 쓰기 경로(`inputs.json` 의 `writable_paths`: `/var/lib/openit/model-runtime`)를 같은 경로로 읽기 전용 마운트한다**(계약 `ModelRuntimeEnv` 가 정한 배치 규칙). 그래서 `OPENIT_MODEL_CACHE_DIR` 는 그 쓰기 경로 안이어야 한다(밖이면 이 영역이 쓸 수 없다: 읽기 전용 루트). 시험(`test_image_declaration`)이 쓰기 경로 선언을 고정한다.
3. **이름 표(`OPENIT_HOSTS_TABLE_FILE`)** 는 계약 `HostsTable` 로 읽는다(최대 6줄). 표가 있을 때만 `socket.getaddrinfo` 를 감싸 표에 있는 이름을 표의 주소로 먼저 푼다(`link/hosts.py`). 접속은 원래 이름으로 하므로 TLS 서버 이름 확인과 `Host` 머리글은 그대로다. 레지스트리 클라이언트(requests)와 이웃 클라이언트(httpx)가 모두 같은 함수로 이름을 푼다. 표가 없으면(같은 서버) 아무것도 바꾸지 않는다.
4. **레지스트리 자격은 한 줄 `사용자:비밀번호` 의 HTTP 기본 인증(RFC 7617)** 이다. 첫 콜론에서 나눈다(RFC 7617 2: user-id 에 콜론이 없고 비밀번호에는 허용). 콜론이 없거나 사용자가 비면 시작할 때 거부한다(계약이 정한 형식이다). ORAS 는 레지스트리의 도전(401 Basic)을 받으면 그 값으로 답한다. 인증이 없는 로컬 레지스트리는 도전이 없어 헤더 없이 그대로 돈다(시험).
5. **가중치 layer 는 어댑터 폴더를 묶은 tar 한 파일**이다(계약 `ModelPackageBlobMediaType` 설명). `pack_adapter_folder` 가 이름순·mtime 0·uid/gid 0·모드 0644·일반 파일만으로 묶어 같은 입력이면 같은 바이트다. `package_loader` 는 `tarfile` 의 `data` 필터(PEP 706)로 푼다. 시험이 파일 시각을 바꿔도 같은 바이트임과 풀 때 경로 이탈·링크·특수 파일 거부를 고정한다.
6. **클라이언트 인증서(`OPENIT_TLS_CERTIFICATE_FILE`·`KEY`)** 는 `link_registry` 가 이웃(레지스트리)을 부를 때 `requests` 세션의 `cert` 로 보인다. 경로만 주므로 새 연결을 열 때마다 파일을 읽는다(인증서 에이전트가 갱신하면 새 연결부터 새 인증서). 레지스트리가 mTLS 를 요구하지 않아도 계약대로 받아 두고 보인다. `package-publish` 도구(관리 노드)는 쓰지 않는다(입력이 계약 Env 가 아니다).

## 왜
- 엔진 주소·이름 표·자격은 계약 `ModelRuntimeEnv` 입력이다. 환경 입력은 스키마의 이름만 받는다(워크스페이스 규칙).
- 이름 표를 `getaddrinfo` 에서 적용하는 것은 `hosts(5)` 와 같은 일이다. 컨테이너 루트는 읽기 전용이라 `/etc/hosts` 를 고칠 수 없고, deploy 가 compose `extra_hosts` 로 넣는 방법은 계약이 이름 표 파일을 입력으로 정한 것과 맞지 않는다. 주소로 직접 접속하면 TLS 서버 이름 확인이 깨진다.
- RFC 7617 은 HTTP 기본 인증의 표준이고 OCI Distribution Spec 이 레지스트리 인증으로 허용한다.
- 같은 입력이면 같은 바이트의 tar 는 패키지 digest 가 입력에서 정해지게 한다(OCI 의 내용 주소 지정).

## 검토한 대안과 버리는 이유
- 이름 표를 모든 클라이언트에 따로 적용(각자 resolver): 클라이언트마다 방법이 달라 같은 표를 두 번 구현한다. 버린다.
- 인증서 파일 내용을 시작할 때 한 번 읽기: 갱신 때 재시작이 필요하다. 계약은 갱신을 에이전트가 한다고 했다. 버린다.
- 어댑터를 `OPENIT_MODEL_CACHE_DIR` 와 별개의 새 경로에 두기: 계약에 경로 입력이 없고 쓰기 경로 선언은 하나(`/var/lib/openit/model-runtime`)다. 버린다.

## 결과
- 얻는 것: 코드에 배치 상수가 없다. 다른 서버의 레지스트리도 같은 코드로 닿는다.
- 감수하는 것: `getaddrinfo` 감싸기는 프로세스 전체에 적용된다(표에 있는 이름만 바뀐다). 열려 있는 keep-alive 연결은 인증서 갱신 뒤에도 옛 인증서를 쓴다. **인증서 갱신 중 파일 교체와 실제 mTLS 레지스트리(Caddy)는 확인하지 못했다**(시험용 레지스트리가 클라이언트 인증서를 요구하게 해 보이는 것까지만 확인했다).

## 되돌리는 조건
엔진이 어댑터 경로를 다른 곳에서 읽어야 하면(계약이 엔진이 보는 어댑터 폴더 입력을 만들면) 2항을 바꾼다.
