# 문진 키오스크 v7 영역 사이 데이터 흐름

기준일 2026-11-10. 출처는 `head/docs/DECISIONS.md`(정본), `head/docs/OPEN_GAPS.md`, `head/docs/STRUCTURE.md` 6절(10/27 개요, 출발점으로만), `head/docs/FLOW.md`, `head/shared/areas.json`, `contracts/areas.yaml`뿐이다. 다른 출처(스키마, 코드, 계약 문서)로 빈 곳을 메우지 않았다.

## 요약

- 흐름 수: 74개(F01~F74). 근거 없이 3)절로 보낸 것: 25항목(C01~C25).
- 외부 참여자 18개와 근거. 외부:환자(D12, D55), 외부:접수(G-SUBJ-1), 외부:저자(D31), 외부:검수자(D92), 외부:승인자(D53), 외부:검토자(D52(1), D71), 외부:직원(D64), 외부:의사(U83), 외부:운영자(D70, D85(3), U97), 외부:병원 시스템(D102), 외부:위험 감지기(D85(2)), 외부:키오스크 기기(D136), 외부:조직 PKI(D113, D136), 외부:데이터셋 담당(G02, D107), 외부:학습 서버(D78, G06, D107), 외부:모델 허브(D51, D73), 외부:이미지 레지스트리(D24), 외부:유지보수 담당(D10).
- 읽은 결정: DECISIONS 전체(D01~D136, 열린 결정 O06·O10·O11·O13·O14·O16·O19, 근거 보강 표 포함). OPEN_GAPS 전체(G·U·D-·L·H·C·E 항목과 11/03~11/07 추가 절). 표 근거 칸에 실제로 쓴 번호는 D번호 79개와 그 밖의 대장 번호(U·G·L·E·O 등) 약 50개다.
- 표를 만든 기준: 최신 결정이 옛 결정을 바꿨으면 최신 기준으로 쓰고 비고에 옛 번호를 적었다. 최신 결정끼리 다르면 표에는 근거가 있는 쪽만 두고 3)절로 보냈다. STRUCTURE E01~E22 중 저장소를 거치던 전달(E02, E04 게시, E06 게시, E09, E10, E15, E16)은 저장소가 소유 영역 안의 컴포넌트가 되었으므로(D126, D49, D100) 영역 안 절로 옮겼다.
- 이 문서는 이미 있는 구현을 읽지 않고 결정 기록에서만 뽑았다. 구현이 결정과 다르면 그 차이는 이 문서에 없다.

## 읽는 법

- 보내는 쪽 → 받는 쪽은 데이터가 가는 방향이다. 요청과 응답이 한 쌍이어도 "무엇이 누구에게서 누구에게 가는가"로 한 줄씩 적었다(요청 쪽 계기가 시작이다).
- 같은 흐름이 여러 영역에 똑같이 가면 한 줄에 영역 이름을 쉼표로 적었다.
- 사람이 영역 화면·서비스를 쓰는 흐름은 공개 입구(platform)와 사람 인증을 거친다(D127, D128, D129). 줄마다 platform을 되풀이하지 않고, 사람 → platform 로그인과 platform → 영역 사용자 식별 전달을 따로 한 줄씩 적었다(F46~F48).
- 엔드포인트 경로, 필드 이름, 값의 모양은 적지 않았다. 결정 문장에 있어도 옮기지 않았다.
- 근거는 DECISIONS의 D번호와 OPEN_GAPS의 U·G·L·E번호다. `STRUCTURE E##`는 10/27 개요표(낡음)의 번호이고 이 표에서는 비고에만 쓴다. 근거 칸에는 결정·대장 번호만 있다.
- 영역 이름은 `contracts/areas.yaml` 14개만 썼다. turn-engine은 영역이 아니다(D104(4) 폐지, D109 퇴역).

## 영역 안이라 뺀 것

- 문진 서비스 안의 Orchestrator와 Session Store 사이(E13), 세션 DB, Trace 전달 대기열(outbox), 그래프 노드 호출: survey-service 안(D62, D126, E13). 문진 서비스의 알림 재시도 큐(L14)와 되묻기 한도 재질문 단계(U100, 설계 확정·구현 전)도 같다.
- 문항 저작 → 문항 저장소(E02), 초안 변환기·검수 워크플로: question-authoring 안(D126, D31).
- 합성 데이터 → 데이터셋 저장소(E04의 게시 쪽): synthetic-data 안(D100, D126).
- 모델 개발·평가 → 모델 레지스트리(E06의 게시 쪽): model-lab 안(D49, D126). GPU 호스트에서 레지스트리로 가는 길은 호스트 밖에서 보이는 입구가 없다(U69, 3)절 C16).
- 게이트 → 릴리스 레지스트리의 쓰기(E09·E10), 판정 기록: release-gate 안(D03, D126).
- 로그 저장소 → 비식별 처리기(E15), 비식별 처리기 → 실패 사례 저장소(E16), 사례 분류·검토 큐: ops-feedback 안(D15, D126).
- LoRA-A 출력 보증과 값 규칙 적용, 어댑터 적재: model-runtime 안(D104(3), D115).
- 영역 게이트웨이와 나가는 CONNECT 터널(허용 목록은 Exposure.egress): 각 영역 안(D128).
- Keycloak·oauth2-proxy·Caddy 사이, step-ca → 공개 입구 인증서, 감시 스택 내부, 백업 저장소 내부: platform 안(D127, D132).
- deploy의 스케줄러와 digest 잠금 파일 갱신: deploy 안(D24, D111).
- 키오스크 앱과 직원 콘솔 앱, STT 어댑터: kiosk-frontend 안(D65(3), D65(6)).
- 영역 DB 컨테이너와 그 영역 사이: 영역 안(D126, D133). 공유 DB는 없다(D126).

## 결정으로 없앤 흐름(참고)

- survey-service → 외부 추적(LangSmith 등): 끈다(D63).
- 컴포넌트가 낸 값의 재검증·재시도: 받는 쪽은 하지 않는다(D104(3), D115). 문진 서비스에서 재호출을 삭제했다(U24).
- 결과를 병원으로 밀어 넣는 전달기(push): 수신처가 정해질 때까지 없다(D102, D85(1)).
- 키오스크 기기 토큰: 없앴다(D136). 환자 참조를 기기 설정으로 주는 길: 없앴다(G-SUBJ-1, 계약 4.0.5).
- 영역 사이 공유 DB와 이웃 저장소 볼륨 공유: 금지(D49, D126).
- turn-engine → 영역(규칙 라이브러리): 퇴역(D104(4), D109).
