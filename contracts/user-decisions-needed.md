# 사용자가 정한 값

**상태: 남은 결정 없음.** UD-01~UD-22 모두 사용자 결정(2026-11-10)으로 정해졌다. 사용자 결정(2026-11-10)으로 UD-01~UD-09 는 권고값과 '관측 최대의 2배' 상한 규칙(학습 데이터로 잰 값에 적용)이 확정되었고, UD-10~UD-18 은 아래 "정해진 값"과 같이 정해졌다. 계약의 `x-basis` 는 "사용자 결정 2026-11-10(UD-n)"을 가리킨다.

## 정해진 값(UD-10~UD-18)

| 번호 | 정해진 값 | 계약 반영 |
|---|---|---|
| UD-10 | 쪽이 아닌 목록의 최대 항목 100개 | 해당 배열의 `maxItems` 100 |
| UD-11 | 나가는 호출 상대 최대 32개 | `Exposure.egress` 의 `maxItems` 32 |
| UD-12 | 응답 문장의 음성 출력(TTS)은 기기 안에서만 하고 외부로 보내지 않는다 | `ResponseSentence` 설명, F24 닫음 |
| UD-13 | 이미지 라벨 값 최대 8000자 | `ImageLabelValue` |
| UD-14 | 식별 이름 최대 63자 | 식별 이름 값들의 `maxLength` 63 |
| UD-15 | 서버 수는 서비스 수 이하에서 자유롭게 하고 서비스와 서버의 대응은 배치 설정으로 한다 | `DeploymentLayout.servers` 의 `maxItems` 10 |
| UD-16 | 학습 서버가 model-lab 에서 대기 중인 학습 요청과 파일을 HTTPS 로 당겨 간다 | `listTrainingRequests`, `downloadTrainingInputFile`, F66 닫음 |
| UD-17 | 키오스크 유휴 초기화 60초(D88 U10, 설정 값) | `TimeBudgetTable.kiosk_idle_reset` |
| UD-18 | 위험 감지가 꺼져 있는 동안은 외부 감지기의 입력 경로를 만들지 않고 켤 때 정한다 | F37 은 신호를 받는 작업만 둔다 |

## 원래 목록

표준, 측정(데이터셋 정본과 서버의 어댑터 파일), 결정 기록의 어느 것에서도 값이 나오지 않아 사용자가 정해야 했던 항목과 그때의 권고값이다.

| 번호 | 값 이름(계약의 값) | 무엇을 정해야 하는가 | 참고 조항 | 정해진 값 |
|---|---|---|---|---|
| UD-01 | 이름·제목 글의 최대 길이(`ProblemTitle`, `QuestionnaireTitle`, `DatasetName`, `CandidateLabel`, `MetricSlice`) | 화면과 목록에 보이는 이름의 최대 글자 수 | 실측 문항 질문 문장 최대 56자, 한 줄 표시 폭. 측정할 정본이 없다 | 200자 |
| UD-02 | 사유·설명 글의 최대 길이(`ProblemDetail`, `DecisionReason`, `CheckMessage`, `PreviewWarning`) | 사람이 쓰는 사유와 서버가 쓰는 설명의 최대 글자 수 | 반려·활성화·롤백 사유는 승인 기록에 남는다. 환자 발화는 넣지 않는다(D88). 측정할 정본이 없다 | 사유와 오류 설명 4000자, 검사 메시지와 경고 1000자 |
| UD-03 | `/metrics` 본문의 최대 크기(`PrometheusExposition`) | 지표 읽기 응답의 최대 바이트 | Prometheus 는 본문 크기 상한이 기본 없음. 서비스 지표 수를 아직 잴 수 없다 | 8 MiB |
| UD-04 | 시작 코드의 유효 시간(`StartCodeTtlSeconds` 의 기본 300초, 계약은 NIST 상한 600초까지 허용) | 직원이 코드를 발급하고 환자가 키오스크에 입력하기까지 허용할 시간 | NIST SP 800-63B-3 5.1.3.2 는 일회용 비밀 유효 시간을 최대 10분으로 한다. 대기 줄이 길면 길어야 하고 짧을수록 안전하다 | 300초 |
| UD-05 | 문항 자료 파일의 최대 크기(`MaterialFileContent`) | 저자가 올리는 PDF 등의 최대 바이트 | 지원 형식을 정하지 않았고(D33) 실제 자료 크기가 없다 | 20 MiB |
| UD-06 | 문항 초안 미리보기의 최대 길이(`PreviewText`) | 사람이 읽는 미리보기 글의 최대 글자 수 | 실측 문항 31개, 질문 문장 최대 56자. 문진표 하나 전체 분량은 측정하지 않았다 | 20000자 |

| UD-08 | 키오스크 기기 수의 상한(`DeviceAllowlist.devices`, `DeploymentLayout.device_placements`) | 한 설치에서 등록할 기기의 최대 수 | 설치처를 전제하지 않는다(설치처 차이는 설정 값). 기기 수에 대한 결정이 없다 | 1000대 |
| UD-09 | 컨테이너가 쓰는 경로 수의 상한(`ContainerInputs.writable_paths`) | 읽기 전용 루트 파일시스템에서 쓰기를 허용할 경로의 최대 수 | ADR 0004(루트는 읽기 전용, 로그는 표준 출력). 영역 이미지의 쓰기 경로를 아직 모은 적이 없다 | 16개 |

## 프로젝트 선택 상한(UD-19~UD-22, 사용자 결정 2026-11-10)

표준 조항은 이 값들의 최대를 정하지 않는다. 아래 참고 조항은 지원 하한, 상호운용 범위, 다른 클레임의 길이를 보여 줄 뿐 값을 유도하지 않으므로 프로젝트 선택이며, 사용자 결정(2026-11-10)으로 권고값 그대로 정했다. 계약 값의 `x-basis` 가 UD 번호를 가리킨다.

| 번호 | 값 이름(계약의 값) | 무엇을 정해야 하는가 | 참고 조항 | 정해진 값 | 왜 이 값인가 |
|---|---|---|---|---|---|
| UD-19 | URI·헤더·경로 문자열 최대 길이(`ProblemType`, `ProblemInstance`, `JsonPointer`, `ForwardedClientCertValue`, `RoutePathPrefix`, `AuthenticateChallenge`, 주소류 `*Url`) | 주소와 헤더 값의 최대 글자 수 | RFC 9110 4.1 은 모든 구현이 최소 8000옥텟의 URI 를 지원하라고 권고하고 5.4 는 필드 한도를 구현이 정하게 한다. 최대를 정하는 조항은 없다 | 8000 | RFC 9110 이 모든 구현에 지원을 권고하는 크기와 같아 어떤 표준 구현도 받아들인다. URI 는 퍼센트 인코딩으로 ASCII 라 글자 수와 옥텟 수가 같다 |
| UD-20 | 시각 표기 프로파일(`Timestamp`) | 소수 초 자릿수와 최대 길이 | RFC 3339 는 소수 초 자릿수를 제한하지 않는다. 9자리까지(나노초)와 오프셋을 더하면 35자다 | 소수 9자리 이하, 35자 | PostgreSQL·Python(6자리)과 Go·Java(9자리)의 출력이 자르지 않고 모두 들어간다. 9자리와 오프셋을 더하면 35자다 |
| UD-21 | 수 값의 안전 범위(`SlotNumber`) | 수 값의 절대 한계 | RFC 7493 2.2 는 ±(2^53-1) 밖의 수를 상호운용 위험으로 본다. 칸마다의 범위는 칸 규격이 정한다 | ±(2^53-1) | 화면(JavaScript)까지 정수가 손실 없이 오가는 범위다. 정수의 정확 교환 범위이지 소수의 정밀도 보장은 아니다 |
| UD-22 | 토큰 문자열 길이(`OidcClientId`, `TokenId`, `JwsAlgorithmName`) | client_id, jti, alg 문자열의 최대 길이 | RFC 9068 과 RFC 7519 는 길이를 정하지 않는다. sub 는 OIDC Core 가 255로 정한다 | client_id 와 jti 255, alg 16 | client_id·jti 는 같은 토큰의 sub(OIDC Core 5.1, 255 ASCII 이하)와 같은 길이다. alg 는 접근 토큰의 JWS 서명 알고리즘 이름이고 RFC 7518 3.1 표의 최장이 5자(PS512 등), 뒤에 등록된 ES256K·EdDSA 가 6자 이하라 16자면 여유가 있다(JWE 키 관리 이름은 받지 않는다) |
