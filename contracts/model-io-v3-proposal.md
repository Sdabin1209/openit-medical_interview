# 모델 입출력 v3 제안 (활성 아님)

모델 입출력 v2(`model-io-v2`)는 지금 학습된 어댑터가 쓰는 형식이며 `components.yaml` 의 LoRA-A·LoRA-B 값이 그 사본이다. 이 문서는 v2 에 없는 것을 다음 버전 후보로 모아 둔다. 이 문서의 내용은 계약의 값이 아니다. 데이터셋이 반영하고 어댑터를 다시 학습해 `ModelIoVersion` 에 `model-io-v3` 가 더해질 때 계약에 넣는다.

## v3 후보

| 항목 | 내용 | 켜지는 기능 | 근거 |
|---|---|---|---|
| 확인 중 상태 | LoRA-A 입력에 선택 칸 `confirming`(칸 키에서 `{value, status}`)을 더한다 | 확인(CONFIRM)에 대한 환자의 답을 모델이 어느 값의 답인지 안다 | 사용자 결정 2026-11-10, DC-01 |
| 질문의 뜻·대상을 묻는 분류 | `reason` 에 `MEANING_ASKED` 를 더하고 짝이 되는 action 을 정한다 | 되묻기 한도(`ReaskLimit`)에 세지 않는 설명 요청, 설명 요청이 한 문항에서 3번 이어지면(`ExplainStreakLimit`) 서비스가 고정 문장으로 직원 도움을 안내 | 사용자 결정 2026-11-10, DC-02 |

## v2 에서의 동작

- 되묻기 한도(처음 질문 1회와 되묻기 2회)는 REASK 와 CONFIRM 이 이어지는 횟수를 센다. 질문의 뜻을 묻는 말은 모델이 따로 분류하지 못하므로 v2 에서는 한도를 면제할 수 없다.
- 한도에 닿으면 서비스가 문항을 건너뛰고 결과에 `REASK_LIMIT` 를 남기며 서비스의 고정 문장으로 안내한다. 모델에 거짓 사유를 보내지 않는다.
- `ExplainStreakLimit` 과 `StaffHelpNotice` 는 v3 부터 동작한다.
