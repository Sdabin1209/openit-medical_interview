# 0003. 사람 말 표와 문장 틀을 정본에서 그대로 옮긴다

## 상태
승인(2026-11-10, 헤드 결정: 모델 입력의 글 조각은 model-runtime 이 libs/model-io 에서 만든다. ADR 0019).

## 맥락
LoRA-B 입력의 topic·known·ask·previous·current·hold 는 LoRA-A 출력에서 표(질환명, 흡연·운동 이름, 술 종류, 단위)와 문장 틀로 찾는 사람 말이다. 정본은 데이터셋의 `contracts/inputs/labels.py` 다(D74). 학습 데이터가 이 글자로 만들어졌으므로 한 글자만 달라도 모델 입력이 학습 분포에서 벗어난다(D77).

## 결정
`core/labels_port.py` 에 정본의 표와 함수(사람 말 설명표, ask 문장 틀, LoRA-B 입력 만들기)를 줄 단위로 그대로 옮기고, 형식·타입 검사를 이 파일에 걸지 않는다(`# fmt: off`, `# ruff: noqa`, pyright `ignore`). 형이 있는 경계는 `core/compose.py` 의 함수 둘이다. 문항 순서와 건너뛰기는 DB 를 읽는 정본 `next_after` 대신 요청의 순서표로 `bank.py` 가 한다. 다음 질문 문장은 문항 은행의 것이라 호출하는 쪽이 준다.

## 왜
- 표와 문장 틀을 다시 쓰면 글자가 어긋나는 곳이 생긴다. 어긋남은 모델 성능으로만 드러난다.
- 정본과의 같음을 두 시험이 지킨다: `tests/contract/test_phrases_match_labels.py` 는 정본 파일을 직접 읽어 같은 이름의 정의가 소스까지 같은지 본다. `tests/dataset` 은 학습 파일 B 입력 46655건을 A 정답·state·다음 질문 문장에서 만든 것과 견주어 내용이 모두 같고 직렬화는 46645건이 바이트까지 같다(10건은 학습 파일이 정렬되지 않음).

## 검토한 대안과 버리는 이유
- **형식을 고쳐 타입·린트를 맞추기:** 정본과 대조가 어려워지고 옮기다 글자가 바뀔 위험이 생긴다.
- **정본을 import:** 정본은 `common`(정규화기)과 DB 에 기대고 리포 밖 파일이다.
- **서비스가 만들게 두기:** 데이터셋 입출력 규칙은 model-runtime 한 곳에만 닿는다(ADR 0019, 헤드 결정).

## 결과
- **얻는 것:** 서빙이 학습과 같은 글을 만든다. 정본이 바뀌면 시험이 먼저 깨진다.
- **감수하는 것:** 이 파일은 린트·타입 검사를 받지 않는다. 정본이 바뀌면 다시 옮긴다.

## 되돌리는 조건
데이터셋이 문장 틀을 표 데이터(JSON)로 배포하면 그 데이터를 읽는 코드로 바꾸고 이 ADR 을 대체한다.
