# 0005. 켜지 않은 고쳐 쓰기 규칙(R1·R3)과 R2 의 날수

## 상태
승인(2026-11-11, model-runtime 영역 작업자). 변경 요청 model-runtime-002 에 대한 헤드 결정(계약 9.0.0 이 `ActionExtractionRules` 에 'R1·R3 명시적 비활성'과 R2 날수 7·31·366 을 이유와 함께 적었고 `dataset-change-requests.md` 에 DC-11 을 더했다)을 코드에 옮긴다. [ADR 0002](0002-출력-검증과-직렬화의-구조.md) 를 보강한다.

## 맥락
D115 의 값 고쳐 쓰기 R1(횟수가 있으면 '마심'으로 고친다)·R3(최대 음주량 < 평소 음주량이면 `CONFIRM/CONFLICT_MAX_BELOW_USUAL`)은 규칙 데이터(술 종류별 mL 환산표, R1 규칙)가 데이터셋 정본에 없다. R2(횟수 > 날수)는 기간별 날수가 정본에 없다.

## 결정
- **R1·R3 은 적용하지 않는다.** 코드에 이름과 이유를 `rules.DISABLED_RULES`(`DisabledRule(name, what, reason)` 두 개, 공개 API)로 적는다. 이유는 '정본 없음, DC-11'이다. 시험이 (1) 비활성 목록이 R1·R3 이고 이유에 DC-11 이 있음, (2) `Rewrite` 가 세 가지(`NEXT_ITEM_FILLED`, `OUT_OF_RANGE`, `COUNT_EXCEEDS_DAYS`)뿐임, (3) R1 사례(`does_not_drink` 참 + 횟수)와 R3 사례(최대 1잔 < 평소 5잔)를 검증기가 고쳐 쓰지 않음을 고정한다. 켜는 일은 이 시험을 바꾸는 일이라 눈에 띈다.
- **R2 의 날수는 달력의 가장 긴 값 7(주)·31(달)·366(해)** 이다(`guard._DAYS_IN_PERIOD`). 정규화기의 값이 정본에 없어 정할 수 없으므로 가장 긴 값을 쓴다. 시험이 경계(가장 긴 값까지는 되묻지 않고 하나 넘으면 되묻는다)를 고정한다.

## 왜
- 값을 지어내지 않는다(워크스페이스 규칙). 정본이 데이터를 주면 켠다(DC-11).
- 가장 긴 달력 값은 '가능한 답을 불가능하다고 되묻는' 일이 없는 안전한 쪽이다. 과소 검출(실제로는 불가능한 횟수를 통과시킴)은 있을 수 있으나 환자의 가능한 답을 틀렸다고 하는 일은 없다. 근거 측정: 학습 서버 정답에서 받아들인 최대 횟수는 주 7, 월 30, 년 15 이고 모두 위반 0 이다(변경 요청 model-runtime-002 의 측정, 2026-11-10).

## 검토한 대안과 버리는 이유
- **정규화기 코드에서 값을 역설계해 R1·R3 을 만들기:** 정본이 아닌 코드의 추정이다. 틀리면 환자 답을 잘못 고친다. 버린다.
- **주 7·월 30·해 365 같은 평균 값:** 가능한 답(31일 달에 31번)을 불가능하다고 되묻는다. 버린다.
- **R1·R3 을 코드에 주석으로만 남기기:** 켜지지 않았다는 사실이 시험으로 고정되지 않는다. 버린다.

## 결과
- 얻는 것: 켜지 않은 규칙이 이름·이유와 함께 코드와 시험에 있다. 날수의 근거가 한 곳에 있다.
- 감수하는 것: R1·R3 사례의 출력은 모델이 쓴 대로 나간다. R2 는 실제 날수(예: 월 30)보다 큰 횟수 31 을 통과시킨다. **학습 파일 정답으로 위반 0 을 재는 시험(`-m dataset`)은 학습 파일이 이 트리에 없어 이번 작업에서 돌리지 못했다**(`MODEL_IO_DATASET_DIR` 없음).

## 되돌리는 조건
정본(`contracts/inputs`)이 환산표·R1 규칙·기간별 날수를 데이터로 주면(DC-11 처리) 규칙을 켜고 `DISABLED_RULES` 에서 뺀다.
