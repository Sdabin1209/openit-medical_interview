# 0003. 라우트 생성과 인증 요구

## 상태
승인(2026-11-10, platform 작업). 계약에 닿는 판단은 `docs/change-requests/platform-003.md` 로 헤드에게 넘겼고 계약 9.0.0 이 답했다(2026-11-11 개정: 아래 '결과'와 '되돌리는 조건').

## 맥락
입구는 영역들의 노출 선언(`Exposure`, 이미지 라벨 `io.openit.exposure`)에서 경로를 만들고 대상(`ExposureAudience`)마다 인증을 건다. 계약은 (1) 같은 공개 경로를 두 영역이 열면 시작하지 않는다, (2) `MACHINE_TOKEN`·`DENIED` 와 건강·지표 경로는 입구로 내보내지 않는다, (3) 기기는 mTLS 이고 입구가 `X-Forwarded-Client-Cert` 를 지우고 다시 쓴다(`SANITIZE_SET`)고 정한다. 어떤 역할이 필요한지는 계약 OpenAPI 의 작업 `security` 에만 있다.

## 결정
- **입력:** `OPENIT_EXPOSURES_DIR` 의 `<서비스 이름>.json`(파일 이름은 `ServiceName`, 내용은 `Exposure`)을 생성된 계약 타입으로 검증한다. `./deploy` 가 이미지 라벨에서 이 폴더를 채운다(라벨이 없는 이미지는 건너뛴다).
- **라우트 = 노출 선언 × 계약의 작업 인증 요구:** 노출 선언의 경로 접두어에 드는 작업(`contracts/openapi/<영역>.yaml`, 읽기만)마다 Envoy 라우트 하나(경로 템플릿을 정규식으로, 메서드 일치)를 만든다. 대상별로 작업의 `security` 에서 그 대상을 허용하는 요구의 역할 합집합만 연다: `HUMAN_OIDC` 는 `oidc`, `DEVICE_MTLS` 는 `device_mtls`, `EXTERNAL_MACHINE_TOKEN` 은 `machine_token`(`area_mtls` 가 함께 있는 요구는 같은 서버 안의 호출이라 제외). 접두어에 든 작업이 그 대상을 허용하지 않으면 그 대상에게는 열지 않는다. 허용하는 작업이 하나도 없으면, 역할 이름이 계약 열거에 없으면, 같은 `(경로, 메서드)` 를 두 영역이 열면 설정을 만들지 않고 멈춘다(`./deploy doctor` 가 먼저 알린다). 작업이 없는 접두어(정적 화면)는 대상만 건다.
- **인증 필터 순서:** Lua(위조 헤더 제거, 기기 허용 목록, 세션 확인 건너뛰기 표시) → ext_authz(oauth2-proxy, 세션 쿠키 확인) → Lua(접근 토큰을 `Authorization: Bearer` 로) → jwt_authn(서명·`iss`·`aud`·`exp`) → RBAC(역할) → router.
- **기기(DEVICE_MTLS):** 입구는 클라이언트 인증서를 선택으로 요청하고(`require_client_certificate: false`) 조직 PKI 루트(`OPENIT_DEVICE_CA_CERTIFICATE_FILE`)로 검증한다. 모르는 CA 의 인증서는 핸드셰이크에서 거절된다. 인증서가 있으면 Lua 가 `(주체 CN, 일련번호)` 를 허용 목록(`DeviceAllowlist`, 설정에 포함, 비밀이 아니다)과 대조해 없으면 403 이다(일련번호는 앞의 0 을 떼고 소문자로 비교). 기기 경로의 RBAC 는 "클라이언트 인증서의 이름이 있다"(`authenticated.principal_name` 정규식 `.+`)이다. 이름 없는 `authenticated` 는 인증서 없이 TLS 이기만 해도 맞아서 쓰지 않는다.
- **XFCC:** HCM `forward_client_cert_details: SANITIZE_SET`, `set_current_client_cert_details.subject: true`. 인증서가 없으면 클라이언트가 보낸 값은 지워지고, 있으면 검증한 인증서로 덮는다(계약의 예 `Hash=…;Subject="CN=kiosk-01"`).
- **사람(HUMAN_OIDC):** `Authorization: Bearer` 가 없고 기기 인증서도 없으면 ext_authz 가 oauth2-proxy 에 세션을 묻는다. API 경로(`/v1/`)는 401, 그 밖(화면)은 로그인 화면으로 302 이다. 세션이 있으면 oauth2-proxy 가 접근 토큰을 주고 Lua 가 `Authorization: Bearer` 로 옮긴다. Bearer 를 직접 보낸 요청은 세션 확인을 건너뛴다. 서비스는 토큰을 다시 검증한다(계약: 서비스가 `UserIdentityClaims` 로 검증).
- **외부 기계 호출자(EXTERNAL_MACHINE_TOKEN):** Keycloak 의 client credentials 접근 토큰이다(변경 요청 platform-002). 입구가 JWKS 로 서명·`aud`·`exp` 를 검증하고 `realm_access.roles` 로 가른다.
- **기기와 토큰을 모두 받는 작업:** 같은 라우트에 정책을 합친다. jwt_authn 은 "토큰이 없으면 통과(`allow_missing`), 틀린 토큰은 거절"로 두고 RBAC 가 기기 인증서나 역할 중 하나를 요구한다. 아무 신원이 없으면 401 이 아니라 403 이다(RBAC 의 응답).
- **기본:** 맞는 라우트가 없으면 404. 건강·지표 경로(`/healthz`, `/readyz`, `/metrics`)는 앞에서 404 로 막는다(접두어 `/` 가 있어도). 플랫폼 자신의 로그인 경로(`/realms/openit/`, `/resources/`, `/oauth2/`)만 인증 없이 내장 라우트로 연다. Keycloak 관리 콘솔(`/admin/`)과 `master` realm 은 열지 않는다.
- **시간(계약 TimeBudgetTable):** 상류 연결 1초(`gateway_connect`), 응답 머리글 기다림 55초(`gateway_patient_route`)를 계약 상수에서 읽는다. 서버 전송 이벤트(`text/event-stream`) 작업은 전체 타임아웃을 끄고(0초) 유휴 한도를 heartbeat(15초)의 3배 45초로 둔다(선택값, 측정하지 않았다).
- **나가는 터널(D128):** `Exposure.egress` 가 있는 영역마다 포트 하나(3128 부터)에서 HTTP CONNECT 를 받고, 선언한 상대의 `host:port`(서비스 이름은 `OPENIT_SERVICE_PORT`)로만 이어 주며 그 밖은 403 이다. 영역이 쓸 주소는 `deploy/generated/gateway/egress-proxies.json`(서비스 이름 → `OPENIT_EGRESS_PROXY` 값)에 있다.
- **로그:** 표준 출력에 JSON 한 줄(쿼리를 뺀 경로, 상태, 플래그). 토큰·쿠키·XFCC·쿼리(OIDC 인가 코드)는 남기지 않는다.

## 왜
- 역할이 계약 OpenAPI 에만 있으므로 라우트를 만들 때 그것을 읽어야 최소 권한이 된다. 접두어를 "아래 전부"로 읽으면 직원 전용 작업(`/v1/sessions/{id}/intervention`)이 기기에게 열린다(시험이 이 작업이 열리지 않음을 본다).
- 허용 목록은 설정 값이라 Lua 에 넣어도 비밀이 새지 않고 Envoy 에는 인증서 일련번호로 거르는 표준 기능이 없다. `serialNumberPeerCertificate`(Lua 의 TLS 연결 접근)로 대조한다.
- 영역마다 터널 포트를 따로 두면 "어느 영역의 선언을 적용하는가"가 접속한 포트로 정해진다(CONNECT 요청에는 호출자 신원이 없다).

## 검토한 대안과 버리는 이유
- **노출 선언만으로 경로 접두어 전체를 여는 방식:** 역할을 알 수 없고 다른 대상의 작업까지 열린다.
- **Envoy `ext_authz` 를 직접 만든 작은 서비스로:** 코드가 생기고 oauth2-proxy 가 이미 세션을 안다.
- **oauth2-proxy 를 역방향 프록시로 영역 앞에 두기:** 경로마다 상류 설정이 oauth2-proxy 에 들어가 입구와 둘로 나뉜다.
- **허용 목록을 `verify_certificate_hash` 로:** 계약이 기기 ID 와 일련번호를 정했다(D136). 해시는 다른 값이다.
- **터널을 서비스별 IP 로 거르기:** 컨테이너 IP 는 설치마다 달라 설정으로 쓸 수 없다.

## 결과
- **얻는 것:** 같은 입력은 같은 설정이고(시험), 선언이 계약과 어긋나면 시작 전에 멈춘다. 기기·사람·외부 기계 호출자·터널 시나리오를 컨테이너에서 시험한다(`platform/tests/scenario`).
- **감수하는 것:**
  - 터널은 compose 안쪽 네트워크의 어느 컨테이너든 어느 영역의 포트에도 접속할 수 있다(포트가 곧 영역이다). 네트워크 안의 신뢰 경계가 컨테이너 단위가 아니다.
  - 입구 앞에서 `aud` 불일치는 403 이고 서비스는 401 이다. 계약 9.0.0(`securitySchemes.oidc`·`machine_token` 설명, platform-003 의 3번)이 "서비스는 401 로, 입구의 `jwt_authn` 은 같은 토큰을 403 으로 거절할 수 있고 입구 앞의 상태 코드만 다르며 열리지 않는 것은 같다"고 적었다. 입구의 응답 코드를 401 로 맞추지 않는다(Lua 로 `aud` 를 직접 보면 표준 필터를 쓰지 않게 된다). 시험은 401 또는 403 을 허용한다.
  - JOSE 헤더 `typ`(`at+jwt`)은 입구가 보지 않는다(Envoy `jwt_authn` 에 옵션이 없다). 서비스가 계약대로(`AccessTokenHeader`) 거절한다. Keycloak 이 `at+jwt` 를 내는 것은 시험이 본다.
  - 같은 경로의 `GET` 만 지원한 접두어, 경로 템플릿은 한 구간(`[^/]+`)으로 본다.

## 계약 9.0.0 의 확정(2026-11-11)
- **라우트 = 노출 선언 × 작업 `security`가 정본이다.** 계약은 `ExposureRoute` 에 `roles` 를 더하지 않고 `Exposure` 설명과 README '입구의 경로와 역할'에 "입구 설정 생성기가 노출 선언과 계약 작업의 인증 요구를 곱해 라우트를 만든다(입구가 읽는 것은 영역 코드가 아니라 헤드 소유 계약이다)"라고 적었다. 위 결정을 그대로 유지한다.
- **로그인 경로 내장은 계약 밖 내부 구현이다.** `/realms/openit/`, `/resources/`, `/oauth2/` 는 platform 자신의 컴포넌트(identity, identity_proxy)의 경로라 계약에 선언하지 않는다고 확정됐다(README '입구의 경로와 역할'). `ExposureAudience` 에 익명 대상을 더하지 않는다. `_builtin_routes` 의 내장은 그대로이고 관리 콘솔(`/admin/`)과 `master` realm 은 계속 열지 않는다.
- **`platform` 의 egress:** `Exposure.egress` 의 서비스 이름 `platform` 은 OIDC 발급자 주소의 호스트와 포트로 나가는 CONNECT 터널이다(계약 `EgressTarget`). 토큰 엔드포인트와 JWKS 가 이 길을 쓴다. 발급자 주소가 설치처 값이라 `gateway.plan` 이 `settings.public_host:public_port` 로 푼다(발급자 호스트가 입구의 이름이고 입구가 같은 서버에서 그 이름으로 듣는다). 시험: 단위(터널 허용 목록에 발급자의 `host:port`), 샌드박스(디스커버리 → 토큰 엔드포인트 → JWKS 를 터널로, 발급자가 아닌 포트는 403).
- **브라우저의 한 출처(admin-console-005):** 화면 경로(admin-console 의 `/console/`, `HUMAN_OIDC`)와 survey-service·model-runtime 의 `/v1/` 경로가 한 가상 호스트의 한 라우트 표로 합쳐지고 같은 `(경로, 메서드)` 를 두 영역이 열면 시작하지 않는다는 것은 단위 시험(`tests/unit/test_gateway.py` 의 `test_screen_path_and_both_services_v1_paths_merge_on_one_origin` 등)이 계약의 실제 OpenAPI 로 확인한다. 알림 스트림 경로의 전체 시간 제한 해제(0초)와 유휴 한도 45초도 같다. 샌드박스는 로그인한 화면 경로와 `/v1/` 경로가 한 출처(입구의 한 포트)에서 역할대로 통하는 것을 이미 본다(`test_roles_decide_the_staff_paths`). 확인하지 못한 것: 실제 화면(admin-console 이미지)과의 종단, 알림 스트림을 실제로 오래 열어 두었을 때 oauth2-proxy·입구가 끊지 않는지(oauth2-proxy 는 스트림 응답 경로에 없고 세션 확인만 한다. 시간 제한은 위 값을 설정으로만 확인했다).

## 되돌리는 조건
계약의 `ExposureRoute` 에 역할이 들어오면 계약 OpenAPI 를 읽는 부분을 없앤다(9.0.0 은 더하지 않기로 했다). 계약이 platform 의 로그인 경로를 선언하도록 바뀌면 내장 라우트를 선언에서 만든다.
