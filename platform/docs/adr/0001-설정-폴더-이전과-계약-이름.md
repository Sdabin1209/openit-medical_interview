# 0001. 설정 폴더 이전과 계약 이름

## 상태
승인(2026-11-10, platform 작업). 리포 전체 ADR 0013~0015 의 설정 이름 일부를 대체한다.

## 맥락
기성품 구성(Envoy, Keycloak, oauth2-proxy, step-ca, Prometheus, 레지스트리 앞단)의 설정이 `deploy/` 아래에 있었고(`design.md` 5절), 설치 설정의 이름(`OPENIT_PUBLIC_CERT_MODE`, `institution`, `public-acme` 등)이 계약(`PlatformEnv`, `CaMode`, `IngressCertificateMode`)과 달랐다. 계약이 정본이다.

## 결정
- 설정 파일은 `platform/` 이 갖는다: `platform/caddy`(레지스트리 앞단), `platform/monitoring`(blackbox, Prometheus 설정·규칙·규칙 시험), `platform/src/openit_platform/`(설정 생성기와 `pki.py`). `deploy/` 는 `compose.yaml`, `env.example`, `./deploy`, `images.lock` 만 갖고 `./deploy` 가 `platform/src` 의 생성기를 불러 `deploy/generated/` 에 파일을 만든다(git 제외).
- 사람이 손으로 쓰던 `envoy.yaml` 과 `openit-realm.json` 은 없앴다. 노출 선언과 설치 설정에서 생성한다(ADR 0002, 0003, 0004).
- 설치 설정의 이름을 계약에 맞췄다: `OPENIT_CA_MODE`(`self`·`organization`), `OPENIT_INGRESS_CERTIFICATE_MODE`(`private`·`organization`·`acme-public`), `OPENIT_ACME_DIRECTORY_URL`, `OPENIT_OIDC_ISSUER_URL`, `OPENIT_DEVICE_CA_CERTIFICATE_FILE`, `OPENIT_DEVICE_ALLOWLIST_FILE`, `OPENIT_EXPOSURES_DIR`, `OPENIT_MACHINE_TOKENS_FILE`, `OPENIT_TRUST_LIST_FILE`, `OPENIT_LISTEN_PORT`, `OPENIT_ALERT_RECEIVER_URL`. 옛 이름(`institution`, `public-acme`, `OPENIT_KIOSK_CLIENT_CA_FILE` 등)은 받지 않는다(시험이 거절하는 것을 본다).
- 계약 9.0.0 이 `PlatformEnv` 에 선택 입력 여섯(`OPENIT_PUBLIC_NAMES`, `OPENIT_INGRESS_CERTIFICATE_FILE`, `OPENIT_INGRESS_PRIVATE_KEY_FILE`, `OPENIT_SERVICE_PORT`, `OPENIT_ALERT_SMTP_SMARTHOST`, `OPENIT_ALERT_HEARTBEAT_INTERVAL`)을 더했다(변경 요청 platform-001 의 답). `settings.py` 가 계약 이름과 칸 타입으로 읽고 검증하며 없을 때의 기본값만 정한다.
- 계약 타입은 `openit-gen-contract platform` 으로 `platform/src/openit_platform/contract/models.py` 에 만든다(손으로 옮기지 않는다, ADR 0020).

## 왜
- 계약이 영역 사이 값의 정본이고, 이름이 둘이면 deploy 가 영역에 값을 줄 때 어긋난다(구조 규칙 6).
- 생성하면 노출 선언이 바뀔 때 설정이 같이 바뀌고 손으로 고친 설정과 선언이 어긋나지 않는다.

## 검토한 대안과 버리는 이유
- **옛 이름을 별칭으로 받기:** 이름이 둘이면 어느 쪽이 정본인지 흐려진다. 이 설치는 아직 운영 전이라 옮기는 비용이 작다.
- **platform 설정을 deploy 에 그대로 두기:** `design.md` 5절이 영역 폴더로 옮기라고 정했고, 영역 에이전트가 자기 폴더 안에서 일하게 하려는 것이다.

## 결과
- **얻는 것:** 설정 이름이 계약과 같다. 생성기는 순수 함수라 docker 없이 단위 시험한다.
- **감수하는 것:** `tools/checks/tests/` 의 옛 시험(`test_deploy_pki.py`)이 `deploy/pki.py` 를 읽으므로 새 위치로 따라가야 한다(platform 작업 범위 밖이라 보고서에 적었다). `contract-drift` 점검이 `platform/` 을 훑지 않아 생성물의 어긋남을 점검이 보지 않는다(같은 이유).

## 되돌리는 조건
계약의 이름이 바뀌면 이 ADR 의 이름 표를 따라 바꾼다.
