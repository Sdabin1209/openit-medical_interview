# 0006. 서비스 이미지의 기반 이미지와 빌드 규칙

## 상태
승인(2026-11-10, 헤드 위임. ADR 0004의 이미지 규칙을 구체화)

## 맥락
ADR 0004는 "다단계, 기반 이미지 digest 고정, 비root, 읽기 전용 루트, HEALTHCHECK, OCI 라벨"을 정했다. 어떤 기반 이미지를 쓸지, digest를 어디에 적을지, 버전을 어떻게 다룰지는 정하지 않았다.

## 결정
- 실행 이미지는 `python:3.12-slim-bookworm`(Docker 공식 이미지, 라이선스: Python은 PSF, Debian 구성품은 각 허용형·GPL 혼합 배포판)을 digest로 고정한다. 빌드 단계의 uv는 `ghcr.io/astral-sh/uv`(MIT/Apache-2.0) 이미지에서 바이너리만 복사하며 역시 digest로 고정한다.
- digest는 각 `Dockerfile`의 `ARG ..._IMAGE=<이름>@sha256:...` 기본값에 적는다. 모든 Dockerfile과 compose가 같은 이미지에 같은 digest를 쓰는지 `tools/checks`의 `image-pins`가 점검한다. 템플릿이 정본이고 영역은 `tools/new-area`로 복사한다.
- Python minor(3.12)는 기반 이미지와 `pyproject.toml`의 `requires-python`이 같다.
- 의존 패키지의 버전은 `pyproject.toml`에 쓰지 않고(`uv add`) `uv.lock`이 고정한다. 이미지는 `uv sync --frozen`으로 잠금 파일대로만 설치한다.
- 이미지는 실행 단계에 빌드 도구를 담지 않는다(`.venv`만 복사). 사용자는 `uid:gid 10001:10001`(고정 값으로 읽기 전용 루트와 볼륨 권한을 예측 가능하게 한다).
- `HEALTHCHECK`는 파이썬 표준 라이브러리로 `/healthz`를 본다(slim 이미지에는 curl이 없다).
- 라벨: `org.opencontainers.image.revision/source/version`, `io.openit.service`, `io.openit.contracts`. 값은 `deploy/deploy build`가 git에서 읽어(`git rev-parse HEAD`, `git describe --tags --always`, `git rev-parse HEAD:contracts`, `git remote get-url origin`) bake 변수로 넣는다. 비어 있으면 bake의 `validation`이 빌드를 막는다. 계약 버전은 `contracts/` 폴더의 git tree 해시다(내용이 같으면 같은 값).
- 빌드 컨텍스트는 서비스 폴더다. `libs/` 의 공유 라이브러리는 bake 의 이름 붙은 컨텍스트로 들인다([ADR 0020](0020-계약-타입-생성-공유-라이브러리-계약-적합성-시험.md)).

## 왜
- digest 고정은 같은 입력에서 같은 이미지가 나오게 한다(태그는 움직인다).
- slim은 공식 이미지 중 glibc 호환 wheel(asyncpg 등)을 그대로 쓰면서 작다. Alpine(musl)은 wheel 호환이 낮아 제외했다.
- Dockerfile이 스스로 서는 단위여야 `docker buildx bake --check`(Docker 표준 빌드 검사)가 통과한다. `ARG`에 기본값이 없으면 `InvalidDefaultArgInFrom` 경고가 나서(시험에서 확인) 기본값을 Dockerfile에 두고, 중복은 점검으로 막는다.
- 계약 버전을 사람이 정한 숫자 대신 tree 해시로 쓰는 이유는 추측으로 값을 채우지 않기 위해서다.

## 검토한 대안과 버리는 이유
- **digest를 `docker-bake.hcl` 한 곳에만 두기:** 단일 출처지만 Dockerfile을 직접 빌드하면 빌드 검사가 경고한다. 점검으로 중복을 막는 쪽을 택했다.
- **distroless, Chainguard:** 셸이 없어 HEALTHCHECK·디버깅이 어렵다. 이 규모에서는 이득보다 비용이 크다고 판단했다(측정하지 않음).
- **Alpine:** 위 이유.
- **빌드 컨텍스트를 리포 루트로 하기:** `libs/`가 영역에 필요해지면 그때 바꾼다(되돌리는 조건).

## 결과
- **얻는 것:** 재현 가능한 이미지, 모든 영역이 같은 Dockerfile.
- **감수하는 것:** 기반 이미지 갱신은 템플릿과 모든 Dockerfile의 digest를 함께 바꿔야 한다(점검이 어긋남을 잡는다). 이미지 크기와 시작 시간은 측정하지 않았다.

## 되돌리는 조건
영역이 `libs/`를 이미지에 넣어야 하면 빌드 컨텍스트를 리포 루트로 바꾸는 새 ADR을 쓴다. 기반 이미지의 보안 갱신은 digest를 바꾸는 커밋으로 한다.
