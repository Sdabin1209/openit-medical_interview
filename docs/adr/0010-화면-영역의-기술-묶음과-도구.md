# 0010. 화면 영역의 기술 묶음과 도구

## 상태
승인(2026-11-10, 사용자 결정: 화면 기술은 ADR 0001 그대로 React. 구조는 ADR 0003의 화면 원칙)

## 맥락
ADR 0001은 화면을 TypeScript, React, Vite, Vitest, Playwright로 정했고 ADR 0003은 화면 영역도 같은 원칙(`src/contract/` 생성 타입, `src/components/`, `src/link/`, `tests/`)을 따른다고 했다. 라우팅, 서버 상태, 표, 폼, 접근성 부품, 경계 점검 도구와 설치 방식을 정해야 한다.

## 결정
- 구성: React 19 + Vite + TypeScript strict(`strict`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, `verbatimModuleSyntax`). React 공식이 권하는 빌드 도구가 Vite다.
- 라우팅 react-router, 서버 상태 @tanstack/react-query, 표 @tanstack/react-table(v9 `useTable` API), 폼 react-hook-form, 접근성 부품 Radix UI(`@radix-ui/react-dialog`). 모두 MIT(npm 메타데이터와 설치본의 `license` 칸으로 확인, `openit-check licenses`가 매번 본다).
- 계약 타입: `openapi-typescript`(MIT)로 OpenAPI에서 `src/contract/*.d.ts`를 생성한다. 손으로 고치지 않는다. 템플릿에는 생성 파이프라인을 시험하는 예시 계약(`tests/contract/fixtures/health.openapi.yaml`)이 있고, 시험이 "생성 결과와 커밋된 파일이 같은지" 확인한다.
- 구조: 컴포넌트는 `src/components/<이름>/` 폴더 하나다(JSX, 자기 파일, `index.ts`). 컴포넌트는 데이터를 props로 받는다. 서버 통신은 `src/link/`에서만 한다.
- 경계 점검: ESLint(flat config) + `eslint-plugin-boundaries`(MIT)로 의존 방향을 막는다. 컴포넌트는 `contract`와 자기 폴더만 import하고(다른 컴포넌트, link 금지), link는 `contract`만 import하며, contract는 아무것도 import하지 않는다. `fetch`·`XMLHttpRequest`·`WebSocket`은 `src/link/` 밖에서 금지(`no-restricted-globals`). 규칙을 어긴 fixtures를 ESLint API로 돌려 위반을 실제로 잡는지 시험한다(`tests/boundaries`). `eslint-plugin-react-hooks`와 `typescript-eslint`의 `strictTypeChecked`도 쓴다. 확장자 없는 상대 import를 풀기 위해 `eslint-import-resolver-typescript`(ISC)를 쓴다(없으면 모든 상대 import가 '알 수 없는 의존'으로 판정되어 경계를 판정하지 못한다. 시험에서 확인).
- 시험: Vitest + @testing-library/react(단위, 계약, 경계), Playwright(브라우저, ADR 0012).
- 설치: 패키지는 `npm install <패키지>`로 버전 없이 설치하고 범위와 `package-lock.json`은 npm이 쓴 그대로 둔다. 이미지 빌드는 `npm ci`로 잠금 파일대로 설치한다. 새 영역은 `tools/new-area web`이 템플릿의 `package.json`을 복사하고 `npm install`로 잠금 파일을 만든다.
- **한 가지 예외로 `typescript`는 주 버전 5를 지정했다(`npm install -D typescript@5`).** 버전 없이 설치하면 TypeScript 7이 들어와 `typescript-eslint`(peer `typescript >=4.8.4 <6.1.0`)와 `openapi-typescript`(peer `typescript ^5.x`)의 peer 조건과 충돌해 설치가 ERESOLVE로 실패했다(2026-11-10 시험). `--force`·`--legacy-peer-deps`는 잘못된 해석을 받아들이는 우회라 쓰지 않았다. 두 도구가 TypeScript 6 이상을 지원하면 버전 지정 없이 다시 설치한다.

## 왜
- 선택은 사용자 결정(ADR 0001)과 지시한 목록이다. 각 도구는 해당 분야의 널리 쓰이는 표준 오픈소스다. 경계 점검 도구는 ADR 0003이 정했다.
- Radix UI는 포커스 가두기, Esc 닫기, aria 속성을 부품이 맡아 접근성 빈틈을 줄인다(시험에서 Esc 닫기를 확인).

## 검토한 대안과 버리는 이유
- **Next.js, Remix 등 프레임워크:** 서버 렌더링이 필요 없고 정적 파일 서빙(ADR 0011)이 단순하다.
- **`--force`로 peer 충돌 무시:** 위 이유.
- **컴포넌트를 파일 하나로:** boundaries 플러그인의 요소 판정이 폴더 단위가 안정적이었다(파일 요소 방식은 deprecated 경고가 나온다).

## 결과
- **얻는 것:** `npm run build`, `npm test`, `npm run lint`, `npx tsc --noEmit`가 모든 화면 영역에서 같다.
- **감수하는 것:** 의존이 많다. `npm audit`가 이 시점에 중간 심각도 10건(`minimatch` 서비스 거부, 개발 도구 쪽 의존)을 보고하며, 정적 이미지에는 들어가지 않는다. 강제 수정(`npm audit fix --force`)은 하지 않았다. eslint-plugin-boundaries v7의 `mode` 옵션 deprecated 경고를 피해 `partialMatch: false`를 썼다.

## 되돌리는 조건
`typescript-eslint`와 `openapi-typescript`가 TypeScript 7을 지원하면 버전 지정을 없앤다. React 외 화면 기술로 바뀌면 ADR 0001부터 대체한다.
