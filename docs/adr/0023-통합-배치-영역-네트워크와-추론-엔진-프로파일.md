# 0023. 통합 배치: 영역 네트워크, 영역 이미지 참조, 추론 엔진 프로파일

## 상태
승인(2026-11-11, 통합 담당). ADR 0004·0008·0013·0021 을 이어 `deploy/compose.yaml` 에 survey-service(와 PostgreSQL), model-runtime, 추론 엔진(vLLM), 화면 둘, 영역 게이트웨이 넷을 넣은 구성을 정한다.

## 결정
- **배치:** `docs/design.md` 6절 그대로다. 서비스 서버에 survey-service·그 DB·platform·화면 둘, 서빙 GPU 서버에 model-runtime·추론 엔진. 한 서버로 시험할 수 있게 같은 compose 파일에 모두 두고 추론 엔진만 compose 프로파일 `inference-engine` 으로 가른다. `OPENIT_INFERENCE_ENGINE_LOCAL`(설치 설정, 기본 true)이 true 일 때만 `./deploy` 가 `--profile inference-engine` 을 준다. 제품 compose 에 시험용 문은 없다(D123). 설치처가 값을 바꿀 뿐이다.
- **영역 네트워크:** 영역마다 `internal: true` 네트워크 하나(ADR 0021). 서비스·영역 DB·그 영역 게이트웨이만 있다. 입구(`ingress-acme`)는 나가는 터널 때문에 터널을 가진 영역(survey-service, model-runtime)의 네트워크에 별칭 `gateway` 로 붙는다.
- **영역 DB:** survey-service 는 자기 PostgreSQL 16 컨테이너(`survey-db`)를 갖는다. Keycloak 의 `postgres` 와 따로다(공유 DB 없음, D126). 비밀번호는 파일(`survey_db_password`).
- **영역 이미지 참조:** compose 는 `image: ${OPENIT_IMAGE_<대상>}` 이고 `./deploy` 가 `images.lock` 의 digest 로 `generated/images.env` 를 만든다(`openit/<대상>@sha256:…`). `pull_policy: never`: 엔진에 있는 digest 이미지를 쓴다. 없거나 lock 에 없으면 `./deploy up` 이 먼저 막는다. 공식 이미지(기반 서비스, vLLM)는 compose 에 digest 로 적는다.
- **추론 엔진 이미지:** `vllm/vllm-openai:v0.33.0`(2026-11-11 `docker buildx imagetools inspect` 로 읽은 digest 고정, Docker Hub 의 안정 태그 `vX.Y.Z` 중 가장 새것). 라이선스 Apache-2.0. 이 환경에서는 받아 돌려 보지 않았다.
- **비밀:** 모두 compose secrets 파일이다. `./deploy secrets init` 이 survey-service 의 DB 비밀번호, 웹 푸시 VAPID 개인키(P-256 PEM, RFC 8292), model-runtime 의 레지스트리 자격(`사용자:비밀번호` 한 줄)과 기계 클라이언트 비밀을 만든다.
- **기계 호출자 표:** `deploy/machine-callers.json`(MachineTokenTable, 비밀 없음). 기본은 survey-service(`inference-caller`) 하나이고 병원 시스템·위험 감지기·model-lab 은 설치처가 항목을 더한다.

## 왜
- 프로파일은 Compose 의 표준 선택 기능이다. 서버마다 다른 compose 파일을 두면 구성이 갈라진다(ADR 0015 U99: 설치처 차이는 설정 값으로).
- digest 참조는 ADR 0004(같은 입력에서 같은 이미지)다.
- 이웃의 저장소를 공유하지 않고 영역마다 DB 를 갖는 것은 D126·D49 다.

## 검토한 대안과 버리는 이유
- **영역마다 compose 파일 분리:** 서버가 하나인 시험·개발 설치에서 파일을 합치는 일이 늘어난다. 프로파일 하나로 같은 효과다.
- **추론 엔진을 compose 밖에서 수동 기동:** 배치가 문서가 되고 `./deploy status` 가 보지 못한다.

## 결과
- **얻는 것:** `./deploy build` 와 `./deploy up` 으로 엔진을 뺀 전체가 뜬다. 결과 확인은 `deploy/docs/INTEGRATION.md`.
- **감수하는 것:** vLLM 컨테이너는 GPU 서버에서 아직 기동해 보지 않았다. 기반 모델 이름(`OPENIT_BASE_MODEL`)은 설치처가 정한다.

## 되돌리는 조건
서버 여러 대로 나눌 때 `DeploymentLayout` 을 deploy 가 읽게 되면 프로파일 대신 서버별 구성으로 바꾼다.
