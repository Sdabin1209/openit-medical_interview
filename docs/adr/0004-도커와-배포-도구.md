# 0004. Docker 이미지와 배포 도구

## 상태
승인(2026-11-10, 헤드 판단, ADR 0002의 배포 방식을 구체화). 이미지 검사는 ADR 0016이 보완하고, 아래 hadolint 문장은 ADR 0017로 대체되었다. 배포 명령 표는 ADR 0013, 0014가 보완한다.

## 결정
- **이미지 규칙(모든 서비스 공통):**
  - 다단계 빌드: 빌드 단계에서 uv로 잠금 파일대로 설치하고, 실행 단계에는 결과만 담는다.
  - 기반 이미지는 digest로 고정한다(태그만 쓰지 않는다).
  - root가 아닌 사용자로 실행하고, 루트 파일시스템은 읽기 전용으로 둔다.
  - `HEALTHCHECK`는 `/healthz`를 본다.
  - 설정은 환경 변수로 받는다. 비밀은 `NAME_FILE`이 가리키는 파일에서만 읽는다(D84). 비밀 값은 이미지, 로그, 오류 응답에 넣지 않는다.
  - OCI 표준 라벨(`org.opencontainers.image.revision`, `.source`, `.version`)과 계약 버전 라벨(`io.openit.contracts`)을 단다.
  - 이미지 검사는 `docker buildx build --check`(Docker 표준 빌드 검사)로 한다. ~~hadolint는 GPL-3.0이라 쓰지 않는다.~~ (대체됨: ADR 0017. hadolint와 Trivy는 ADR 0016)
- **빌드:** 리포 루트의 `docker-bake.hcl`(Docker Buildx Bake, Apache-2.0) 하나에 서비스 이미지를 모두 정의한다. `docker buildx bake`로 전부, `docker buildx bake survey-service`로 하나만 빌드한다. 바뀌지 않은 층은 캐시로 건너뛴다.
- **배포 구성:**
  - `deploy/compose.yaml`(Docker Compose, Apache-2.0) 하나에 서비스, DB, 게이트웨이(Envoy), 사람 인증(Keycloak, oauth2-proxy), 사설 CA(step-ca, Apache-2.0)를 둔다.
  - 이미지는 `deploy/images.lock`의 digest로 고정한다.
  - 설치처마다 다른 값은 `deploy/.env`(예시는 `deploy/env.example`)와 `deploy/secrets/`(git 제외)에 둔다.
- **배포 명령:** `deploy/deploy`(Python, Typer(MIT) CLI) 하나에 하위 명령을 모은다. 내부는 표준 도구(`docker buildx bake`, `docker compose`)를 부를 뿐이다.

  | 명령 | 하는 일 |
  |---|---|
  | `./deploy doctor` | 필요한 도구·버전·포트·비밀 파일이 갖춰졌는지 확인 |
  | `./deploy secrets init` | 비밀 파일 생성(값은 출력하지 않음) |
  | `./deploy build [서비스]` | 이미지 빌드(Trivy 검사 포함, ADR 0016), `images.lock` 갱신 |
  | `./deploy bootstrap` | 신뢰의 뿌리 -> 레지스트리 -> 이미지 push -> 기동(멱등, ADR 0013) |
  | `./deploy pull [서비스]` | `images.lock`의 digest로 레지스트리에서 받기 |
  | `./deploy ca status` / `rotate` / `bundle` / `csr` / `install` | 사설 CA 상태·교체·신뢰 목록(ADR 0014, 0015) |
  | `./deploy up` / `down` / `status` | 띄우기, 내리기, 상태와 health |
  | `./deploy job <이름>` | 잡 한 번 실행(스케줄러가 부르는 것과 같음) |
  | `./deploy backup` / `restore` | 백업, 복원 |
  | `./deploy e2e` | 전체 시험 1회(샌드박스, 제품 구성은 건드리지 않음) |

- **Docker 설정 격리:** 사용자 전역 `~/.docker`를 쓰지 않는다. 호출자가 `DOCKER_CONFIG`를 주면 그것을 쓰고, 없으면 리포의 git 제외 폴더를 쓴다. 엔진 선택은 Docker CLI 공식 우선순위를 따른다.
- **스모크:** 서비스마다 `tests/smoke/`가 이미지를 띄워 `/healthz`, `/readyz`를 확인한다. 호스트 포트는 Docker가 배정한다(고정 포트 없음).

## 왜
- Buildx Bake와 Compose는 Docker의 표준 도구다. 여러 이미지 빌드와 여러 컨테이너 실행을 각각 파일 하나로 정의한다.
- 배포 명령을 하나로 모으면, 서버에서 하는 일이 `git clone` → `./deploy doctor` → `./deploy up`으로 설명된다.

## 검토한 대안과 버리는 이유
- **Makefile:** GNU Make는 GPL이고, 하위 명령의 도움말과 인자 검증을 직접 써야 한다.
- **Kubernetes/Helm:** 한 환경, 단일 서버(ADR 0002 원래 결정 D0002)에 비해 과하다.
- **hadolint:** ~~GPL-3.0.~~ (대체됨: 실행만 하는 도구는 허용, ADR 0017)

## 결과
- **얻는 것:** 이미지와 배포 절차가 모든 서비스에서 같다.
- **감수하는 것:** CLI 하나를 유지해야 한다. 그 CLI는 표준 도구를 부르는 얇은 층으로만 둔다.

## 되돌리는 조건
여러 서버로 확장해야 하면 Compose 대신 오케스트레이터(예: Kubernetes)를 검토한다.
