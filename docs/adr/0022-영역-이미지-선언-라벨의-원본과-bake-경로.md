# 0022. 영역 이미지 선언 라벨의 원본과 bake 경로

## 상태
승인(2026-11-11, 통합 담당. 변경 요청 survey-service-005·model-runtime-003 8번, kiosk-frontend·admin-console 의 같은 문제를 닫는다). ADR 0006, 0020의 라벨 규칙을 보완한다.

## 맥락
`docs/design.md` 4절은 이미지 라벨 `io.openit.jobs`(JobsDeclaration), `io.openit.exposure`(Exposure), `io.openit.inputs`(ContainerInputs)를 정한다. 잡 틀에만 `jobs.json` 과 bake 의 `JOBS` 인자가 있었고 서비스·화면 틀에는 셋을 넣는 길이 없었다. model-runtime 은 `inputs.json` 을 Dockerfile 라벨에 글자 그대로 복사하고 시험으로 같은지 보았다(원본이 둘이 된다).

## 결정
- 원본은 영역 폴더의 `jobs.json`(JobsDeclaration), `exposure.json`(Exposure), `inputs.json`(ContainerInputs) 하나씩이다. Dockerfile 에는 JSON 을 복사하지 않는다.
- 모든 Dockerfile 틀(`templates/service`, `templates/job`, `templates/web`)이 `ARG JOBS`, `ARG EXPOSURE`, `ARG INPUTS`(틀마다 해당하는 것)를 받아 `io.openit.jobs`, `io.openit.exposure`, `io.openit.inputs` 라벨로 단다.
- `deploy/deploy build` 가 영역 폴더의 세 파일을 읽어 한 줄 JSON 으로 모아 bake 변수 `AREA_DECLARATIONS`(대상 이름 → `{jobs, exposure, inputs}`)로 넣고, `docker-bake.hcl` 의 `service`·`job`·`web` 대상이 대상 이름으로 골라 인자에 넣는다. 파일이 없으면 그 라벨 값은 빈 글자다. 밑줄로 시작하는 틀 시험 영역이 아닌 영역에 `inputs.json`(D134: 모든 영역 이미지의 필수 선언)이, 잡 영역에 `jobs.json` 이 없으면 빌드를 막는다.
- 파일이 계약 스키마를 지키는지는 `openit-check declarations`(`tools/checks`)가 JSON Schema 2020-12(format 단언 켬)로 영역 리포에서 한 번 점검한다. platform 의 입구 생성기와 deploy 는 값을 다시 검증하지 않는다(R7). platform 은 계약 타입으로 읽을 뿐이다.
- 서비스 이미지의 잡 호출 모양은 `inputs.json` 의 `processes`(잡 이름별 절대 경로 argv)와 `jobs.json` 이 정한다. deploy 는 `docker compose run` 으로 이 argv 대로 한 번 실행한다. 영역이 `python -m <패키지>.jobs <잡> --requested-at <시각>` 형태를 정하는 것은 영역 선택이다.

## 왜
- 계약 D134·D131 이 선언을 영역 밖에서 읽는 값으로 정했고, 원본을 파일 하나로 두면 라벨과 영역 시험이 같은 값을 본다(ADR 0020 이 `jobs.json` 에 쓴 이유와 같다).
- HCL 에는 파일 읽기 함수가 없다(`file()` 이 없음을 ADR 0020 에서 확인). 그래서 읽는 일은 deploy 가 하고 bake 에는 값만 준다.
- JSON Schema 검증은 계약의 표준 검증 방식(계약 README)이다. 낸 쪽에서 한 번만 검증한다.

## 검토한 대안과 버리는 이유
- **Dockerfile 에 라벨 글자를 복사:** 원본이 둘이 되어 어긋난다(model-runtime 이 시험으로 막던 문제).
- **OCI 이미지 빌드 뒤에 라벨을 덧붙이는 도구(`docker commit`, crane mutate):** 빌드 증명(attestation)과 digest 가 이미지와 어긋난다.
- **deploy 가 이미지 라벨 대신 영역 폴더를 직접 읽기:** 영역은 서로의 구조를 모른다(구조 규칙 1). 이미지가 스스로 서는 단위여야 서버가 달라도 같다.

## 결과
- **얻는 것:** 세 선언이 모든 이미지에서 같은 경로로 나간다. platform 이 노출 선언을 이미지 라벨에서 읽는다(`sync_exposures`).
- **감수하는 것:** 값이 없는 선언은 빈 라벨이다. 라벨 값의 최대 길이를 측정하지 않았다(Docker 가 라벨 값 크기에 상한을 두는지 확인하지 않았다. survey-service 이미지 라벨 실측: inputs 약 2 KB, exposure 약 1.3 KB).

## 되돌리는 조건
BuildKit 이 파일을 읽어 라벨로 쓰는 표준 기능을 내놓으면 deploy 의 읽기를 없앤다.
