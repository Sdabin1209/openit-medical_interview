# 0011. 정적 화면 이미지와 웹 서버

## 상태
실행 단계 기반 이미지의 갈래(stable)는 [ADR 0031](0031-화면-웹-서버는-nginx-mainline.md)이 대체한다(2026-11-23). 나머지는 유효하다.

승인(2026-11-10, 헤드 위임. ADR 0004의 이미지 규칙을 화면 이미지에 적용)

## 맥락
화면 영역은 빌드한 정적 파일을 서빙하는 이미지 하나다. 비root, 읽기 전용 루트, digest 고정, HEALTHCHECK, OCI 라벨이 필요하고 웹 서버도 허용형 라이선스여야 한다.

## 결정
- 빌드 단계: `node:24-bookworm-slim`(digest 고정, MIT) 에서 `npm ci` → `tsc --noEmit` → `vite build`.
- 실행 단계: `nginxinc/nginx-unprivileged:stable-alpine`(digest 고정). nginx는 BSD-2-Clause이고 이 이미지는 nginx 공식 팀이 관리하는 비root 변형(uid 101, 8080)이다.
- 설정(`nginx/default.conf`): `/healthz`는 nginx가 직접 200, `/readyz`는 `index.html`이 있어야 200(없으면 503), `/assets/`는 내용 해시가 파일 이름에 있으므로 오래 캐시(`immutable`), 그 외는 `no-cache`와 `try_files ... /index.html`(SPA 라우팅). `server_tokens off`.
- 실행 조건: 읽기 전용 루트에는 `--tmpfs /tmp`가 필요하다(nginx의 pid·임시 파일 위치. 스모크가 이 조건으로 확인한다).
- `HEALTHCHECK`는 alpine의 busybox `wget`으로 `/healthz`를 본다.
- 라벨과 digest 고정, 빌드 컨텍스트는 서비스 이미지와 같다(ADR 0006). 컨테이너 안 정적 파일은 읽기 전용이다.

## 왜
- nginx는 정적 서빙의 표준이고 비root 공식 이미지가 있어 직접 권한을 조정하지 않아도 된다. 선택지 중 이 이미지는 설정 파일 하나로 SPA 폴백과 캐시 정책이 끝난다.
- 해시 파일은 변하지 않으므로 오래 캐시해도 되고 `index.html`만 갱신을 바로 알리면 된다(Vite 문서의 배포 안내와 같은 방식).

## 검토한 대안과 버리는 이유
- **Caddy(Apache-2.0):** 허용형이고 설정이 간결하다. 비root 공식 변형이 없어 권한 조정이 따로 필요하다.
- **busybox httpd, lighttpd:** busybox는 GPL-2.0이고 lighttpd는 BSD지만 공식 비root·SPA 폴백 문서가 적다.
- **static-web-server(Apache-2.0/MIT):** 허용형이지만 이미지 관리 주체가 개인·소규모 프로젝트다. 측정이나 비교 시험은 하지 않았다.
- **Vite preview를 운영에 쓰기:** Vite 문서가 운영용이 아니라고 안내한다.
- 알림: alpine·debian 기반 이미지에는 GPL 구성품(busybox 등)이 들어 있다. 우리가 쓰는 의존이 아니라 이미지 구성품이며, ADR 0006과 같은 입장이다.

## 결과
- **얻는 것:** 설정 한 파일로 정적 서빙, SPA, 캐시. 스모크가 healthz·readyz·SPA 폴백·비root·읽기 전용 루트·HEALTHCHECK를 본다(이 환경에서 통과).
- **감수하는 것:** 이미지 크기와 응답 성능은 측정하지 않았다. `stable-alpine` 태그의 nginx 버전은 digest가 정한다(시험 시점 1.30.6).
- 화면과 서비스를 같은 출처로 묶는 일(게이트웨이 라우트, 인증)은 영역 계약이 정해진 뒤 정한다.

## 되돌리는 조건
nginx 공식 비root 이미지가 유지되지 않거나 라이선스가 바뀌면 대안(Caddy 등)으로 바꾸는 새 ADR을 쓴다.
