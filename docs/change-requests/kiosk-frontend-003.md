# kiosk-frontend-003: 실패 신호를 준 turn_id 를 다시 보내면 무엇이 오는지 정해져 있지 않다

처리됨(계약 9.0.0(5f3c616, 848dbcb), 영역 e47d70e, 화면 877a72e): 실패 신호를 준 turn_id 는 기록하지 않아 재전송은 다시 처리된다.

## 상태
요청(2026-11-10, kiosk-frontend 작업자). 대상: 헤드. 우선순위 낮음(영역은 안전한 쪽으로 이미 동작).

## 무엇이 어긋나나(읽어서 확인한 것)
- `submitTurn` 설명: "같은 turn_id 를 다시 보내면 같은 결과를 받는다(멱등)", "값을 만들지 못하면 200 으로 failure_signal 을 주며 세션 상태는 바뀌지 않는다". 실패 신호를 준 `turn_id` 를 다시 보내면 같은 실패 신호를 받는지, 다시 처리하는지 적혀 있지 않다.

## 영역이 지금 한 것
연결 실패·503 의 재전송은 같은 `turn_id` 로, `failure_signal` 을 받은 뒤 환자가 다시 보내는 것은 새 `turn_id` 로 보낸다. 어느 쪽 해석이어도 안전하다.

## 요청
실패 신호도 `turn_id` 로 기록되는지 `submitTurn` 설명에 적어 달라.

## 하지 않은 것
계약과 생성물을 영역에서 고치지 않았다.
