# kiosk-frontend-001: 시작 코드에 문진표가 묶였는지 키오스크가 알 방법이 없다

## 상태
요청(2026-11-10, kiosk-frontend 작업자). 대상: 헤드.

## 무엇이 어긋나나(읽어서 확인한 것)
- `startSession` 설명: 문진표는 "시작 코드에 묶인 것, 없으면 요청의 것, 없으면 기기 배치표(U86)의 것, 모두 없고 활성 문진표가 둘 이상이면 환자 선택 순서로 정한다". `SessionStartRequest.questionnaire_id` 는 "코드에 문진표가 묶여 있지 않고 기기 배치도 없을 때만 쓴다".
- 키오스크는 코드에 문진표가 묶였는지, 기기 배치가 있는지 알 수 없다(`listActiveQuestionnaires` 응답은 둘 다 담지 않는다). 문진표 선택이 필요한 경우를 알리는 오류 사유도 `ProblemReason` 에 없다.

## 영역이 지금 한 것
활성 문진표가 둘 이상이면 코드 입력 뒤에 언제나 환자에게 고르게 하고 `questionnaire_id` 를 보낸다(서버가 무시할 수 있다). 하나면 보내지 않는다. 그래서 코드나 기기 배치가 이미 문진표를 정한 설치처에서도 환자가 불필요한 선택을 하게 된다.

## 요청
다음 중 하나를 정해 달라.
1. `startSession` 이 선택이 필요하면 422 와 새 사유(예: `QUESTIONNAIRE_REQUIRED`)로 답한다. 키오스크는 먼저 `questionnaire_id` 없이 보내고(같은 기기·같은 코드 재전송은 멱등이다) 이 사유일 때만 선택 화면을 보인다.
2. `listActiveQuestionnaires` 가 기기 배치 여부를 알린다. (코드 묶임은 이 방법으로 알 수 없다.)
1안을 권한다. 코드 묶임과 기기 배치를 모두 서버 쪽에서 판단하기 때문이다.

## 하지 않은 것
계약과 생성물을 영역에서 고치지 않았다.
