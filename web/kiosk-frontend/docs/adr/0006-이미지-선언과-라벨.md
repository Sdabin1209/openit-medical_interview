# 0006. 이미지 선언(exposure.json, inputs.json)과 라벨

## 상태
승인(2026-11-11, 계약 9.0.0, 헤드 결정 2026-11-10)

## 맥락
deploy 는 이미지 안을 열지 않고 라벨 `io.openit.exposure`(Exposure)와 `io.openit.inputs`(ContainerInputs)만 읽는다. 값의 원본이 Dockerfile 안에 글자로 복사되어 있으면 원본 파일과 어긋난다.

## 결정
- 원본은 영역 폴더의 `exposure.json`, `inputs.json` 이다. Dockerfile 은 `ARG EXPOSURE`, `ARG INPUTS` 를 받아 라벨로 단다. JSON 을 한 줄로 넘기는 일은 deploy build 가 한다. 이 화면은 잡이 없어 `JOBS` 가 없다.
- `exposure.json`: 경로 `/`(화면 파일), 메서드 GET, 대상 `DEVICE_MTLS`(기기 인증서를 낸 키오스크). `egress` 는 비었다(정적 화면은 나가는 호출이 없다. 브라우저가 같은 출처로 부르는 `/v1/` 경로는 survey-service 가 자기 Exposure 로 선언한다). `/healthz`·`/readyz`·`/metrics` 는 입구로 내보내지 않는다(계약 `ExposureAudience` 설명의 D129).
- `inputs.json`: 실행 사용자 101(기반 이미지 nginx-unprivileged 의 기본 사용자, `docker image inspect` 로 확인), 환경 입력 없음(설정을 환경 변수로 받지 않는다), 쓰는 경로 `/tmp` 하나(임시 저장소, 비유지, 사용자 101. 이 기반 이미지가 pid 와 임시 파일을 `/tmp` 에 쓴다는 것은 기반 이미지 설명에서 읽었고 읽기 전용 루트에서의 기동은 이 작업에서 확인하지 않았다), 추가 권한·sysctl 없음, 시작 명령은 기반 이미지의 진입점(`/docker-entrypoint.sh nginx -g "daemon off;"`).
- 시험(`tests/contract/declarations.test.ts`)이 두 파일을 계약 스키마로 검증하고 Dockerfile 이 ARG 로 라벨을 다는지 본다.

## 왜
- OCI 이미지 라벨은 문자열 쌍이고 값은 빌드 인자로 넣는 것이 Docker 의 표준 방법이다. 원본 한 곳(JSON 파일)에서만 쓰면 복사본이 어긋나지 않는다(D117 같은 뜻의 값은 한 번만 정의).
- 낸 값은 받는 쪽이 다시 검증하지 않는다(R7)이므로 낸 영역에서 한 번 검증한다.

## 검토한 대안과 버리는 이유
- **Dockerfile 에 JSON 을 LABEL 로 복사:** 원본과 어긋난다.
- **`/healthz` 등을 DEVICE_MTLS 로 열기:** 입구는 상태 경로를 내보내지 않는다(계약).

## 결과
- 얻는 것: 라벨의 원본이 하나다. 선언이 계약과 어긋나면 시험이 깨진다.
- 감수하는 것: 이미지 빌드는 deploy build 가 인자를 넘겨야 라벨이 채워진다(없으면 빈 라벨).

## 되돌리는 조건
계약의 Exposure·ContainerInputs 가 바뀌거나 기반 이미지(실행 사용자, 쓰는 경로)가 바뀌면 파일을 고친다.
