# 0004. 고령자 접근성과 유휴 초기화

## 상태
확정(2026-11-11, 계약 9.0.0 이 유휴 만료의 주체를 서버로 정했다. 2026-11-10 승인 때의 미정 부분을 확정으로 고친다)

## 맥락
환자는 고령자를 포함한다. 시작 코드와 답은 터치로 누르거나 말하거나 쓴다. 유휴 60초 초기화(UD-17, 계약 `kiosk_idle_reset`)는 입력 중에 화면이 갑자기 사라지게 할 수 있다.

## 결정
- 글자 기본 24px(`font-size: 24px`), 본문·문장은 그 이상, 문진 문장은 2.25rem. 누르는 버튼은 높이 4.5rem 이상, 키패드는 5rem × 7rem. 글자와 바탕의 대비는 7:1 이상 색을 골랐다(WCAG 2.1 SC 1.4.6 AAA).
- 초점 표시는 4px 외곽선(`:focus-visible`), 오류는 `role="alert"`, 상태는 `role="status"`, 문장 변경은 `aria-live="polite"`.
- 유휴 초기화: 입력(포인터·키·터치) 없이 60초면 처음 화면으로 돌아가고 입력과 세션을 지운다. 끝나기 20초 전부터 남은 시간과 "계속하기" 를 보인다. 응답을 기다리는 중, 음성 입력 중, 멈춘 세션에서는 세지 않는다(멈춘 세션은 만료하지 않는다, 계약 `SessionStatus`). 시작 화면은 코드를 입력 중일 때만 센다.
- 유휴 만료의 주체는 서버다. 서버는 마지막 활동(`startSession`, `submitTurn`, `requestStaffCall` 호출, 읽기는 활동이 아니다) 뒤 60초가 지난 ACTIVE 세션을 `EXPIRED` 로 본다(계약 9.0.0 `getSessionState`, `KioskIdleResetSeconds`). 화면은 60초 입력이 없으면 화면만 초기화하고 서버에 알리지 않는다(`endSession` 도 보내지 않는다).
- 이후 서버가 `EXPIRED` 로 답하면 시작 화면으로 돌아간다: `getSessionState` 의 `EXPIRED`(멈춘 동안의 2초 읽기, 409 `SESSION_NOT_ACTIVE` 뒤 읽기, 직원 호출 409 뒤 읽기), `submitTurn` 의 409 `SESSION_NOT_ACTIVE`(뒤 읽은 상태가 `EXPIRED`), `endSession` 의 `status` 가 `EXPIRED`. 끝 화면은 `COMPLETE`·`PARTIAL` 만 보인다. 시험: `tests/unit/app.test.tsx`.
- 끝 화면은 60초 입력이 없으면 경고 없이 처음 화면으로 간다(지울 입력이 없다).

## 왜
- WCAG 2.1 SC 2.2.1(시간 조절 가능, A)은 시간 제한이 있으면 끝나기 전에 알리고 20초 이상 쉬운 동작으로 늘릴 수 있게 하라고 한다. 20초는 그 표준에서 왔다.
- 목표 크기: WCAG 2.2 SC 2.5.8 의 최소 24px 보다 훨씬 크게 잡았고 값은 측정하지 않았다(고령자 사용 시험을 하지 않았다).
- 대비 7:1 은 AAA 기준이다. 색은 계산하지 않고 어두운 회색·파랑·흰색 조합을 골랐다. 측정 도구로 확인하지 않았다.

## 검토한 대안과 버리는 이유
- **경고 없이 60초에 초기화:** SC 2.2.1 위반.
- **`endSession` 으로 서버에 알리기:** 상태가 ENDED_PARTIAL 이 되어 환자가 끝낸 것과 구분되지 않는다. 서버가 스스로 만료시키므로(계약 9.0.0) 알릴 필요가 없다.
- **만료를 끝 화면으로 보이기(이전 구현):** 만료된 세션에는 지울 환자 입력이 이미 없고 다음 사람이 바로 시작할 수 있어야 하므로 시작 화면으로 보낸다.

## 결과
- 얻는 것: 입력 도중 사라지는 일이 없고 다음 사람에게 입력이 남지 않는다.
- 감수하는 것: 화면의 60초 타이머(입력 기준)와 서버의 60초(마지막 활동 호출 기준)는 시작점이 달라 같은 순간에 끝나지 않는다. 화면이 먼저 초기화하면 서버 세션은 만료될 때까지 열려 있고, 서버가 먼저 만료시키면 다음 호출에서 `EXPIRED` 로 알게 된다. 두 경우 모두 시작 화면으로 모인다. 크기·대비는 도구와 사용자로 검증하지 않았다.

## 되돌리는 조건
계약이 유휴 만료의 주체나 활동의 정의를 바꾸면 그에 맞춘다. 사용자 시험에서 크기나 대비가 부족하면 값을 바꾼다.
