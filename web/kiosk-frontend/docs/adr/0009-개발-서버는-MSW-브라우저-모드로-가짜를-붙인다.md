# 0009. 개발 서버는 MSW 브라우저 모드로 가짜 survey-service 를 붙인다

## 상태
승인(2026-11-26).

## 맥락
`npm run dev` 로 띄운 화면에는 survey-service 가 없어 시작 코드 화면 뒤로 나아가지 못했다. 가짜 survey-service(`tests/fakes/survey-service.ts`)는 단위 시험(MSW Node)과 브라우저 시험(`page.route`)에만 붙어서, 화면을 고칠 때마다 시험을 돌려야만 결과를 볼 수 있었다.

## 결정
- 개발 서버에서만 MSW 의 브라우저 모드(`setupWorker`, Service Worker)로 같은 가짜를 붙인다. 진입점 `dev/main.tsx` 가 워커를 띄운 뒤 `src/main.tsx` 를 부른다.
- `vite.config.ts` 의 플러그인 `openit-dev-mock` 이 `serve` 명령에만(미리보기·vitest 제외) 진입점을 `dev/main.tsx` 로, 정적 폴더를 `dev/public` 으로 바꾼다. 워커 파일 `dev/public/mockServiceWorker.js` 는 MSW CLI(`msw init dev/public --save`)가 만들고 `package.json` 의 `msw.workerDirectory` 로 설치 때 갱신된다.
- MSW 처리기는 `tests/fakes/msw-handlers.ts` 하나를 Node 시험(`tests/fakes/msw.ts`)과 개발 서버가 함께 쓴다(`msw/node` 는 브라우저에서 불러올 수 없어 나눴다).
- 끄려면 `VITE_DEV_MOCK=off npm run dev`.

## 왜
- MSW 는 이미 이 영역의 시험 의존이고, 브라우저 모드는 MSW 의 공식 사용법이다. 가짜를 새로 만들지 않고 시험과 같은 것을 쓰므로 계약 타입과 어긋나면 tsc 가 막는다.
- `src` 와 운영 빌드를 바꾸지 않는다. Dockerfile 은 `src` 만 복사하고, 빌드 산출물(`dist`)에 MSW 와 워커 파일이 없음을 확인했다(2026-11-26).

## 검토한 대안과 버리는 이유
- `src/main.tsx` 에서 `import.meta.env.DEV` 로 동적 import: 이미지 빌드(Dockerfile 은 `src` 만 복사)의 tsc 가 `dev/`·`tests/` 를 찾지 못하고, `src` 의 경계 규칙에 시험 코드가 들어온다.
- 워커 파일을 `public/` 에 두기: 운영 이미지에 시험용 Service Worker 가 실린다.
- Vite 프록시로 실제 survey-service 에 붙이기: 화면 작업자가 서비스·인증서·모델을 띄워야 한다. 실제 서비스와의 만남은 배포 통합 시험(E2E)의 몫이다.

## 결과
- 얻는 것: `npm ci && npm run dev` 만으로 시작 → 대화 → 끝 화면을 눌러 볼 수 있다. 새로 고침하면 가짜 상태가 처음으로 돌아간다.
- 감수하는 것: 가짜의 동작만 보인다(실제 모델 문장·시간 아님). headless Chromium 은 `SpeechRecognition.available()` 에서 죽으므로([0002](0002-음성은-기기-안에서만.md)) 개발 서버 확인을 자동화할 때는 시험의 음성 대역을 쓴다. 일반 Chrome 에서는 해당 없음.
