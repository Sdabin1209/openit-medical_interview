# 0011. 개발 서버는 MSW 브라우저 모드로 가짜 백엔드를 붙인다

## 상태
승인(2026-11-26).

## 맥락
`npm run dev` 로 띄운 화면에는 oauth2-proxy·survey-service·model-runtime 이 없어 로그인 확인(`/oauth2/userinfo`)에서 바로 막혔다. 가짜 백엔드(`tests/fakes/backend.ts`)는 Vitest(`fakeFetch`)와 브라우저 시험(`page.route`)에만 붙었다.

## 결정
- 개발 서버에서만 MSW 의 브라우저 모드(`setupWorker`)로 같은 가짜를 붙인다. 진입점 `dev/main.tsx` 가 `/v1/`·`/oauth2/` 요청을 `createFakeBackend().handle` 로 넘기는 처리기 하나로 워커를 띄운 뒤 `src/main.tsx` 를 부른다.
- 역할은 기본으로 모두 준다. 주소에 `?roles=staff,clinician` 처럼 주면 그 역할로 본다(메뉴와 권한 없는 화면 확인용).
- `vite.config.ts` 의 플러그인 `openit-dev-mock` 이 `serve` 명령에만(미리보기·vitest 제외) 진입점을 `dev/main.tsx` 로, 정적 폴더를 `dev/public` 으로 바꾼다. 워커 파일은 MSW CLI(`msw init dev/public --save`)가 만든다. MSW 를 개발 의존으로 더했다(키오스크가 이미 쓰는 것, MIT).
- 끄려면 `VITE_DEV_MOCK=off npm run dev`.

## 왜
- 키오스크 [ADR 0009](../../../kiosk-frontend/docs/adr/0009-개발-서버는-MSW-브라우저-모드로-가짜를-붙인다.md)와 같은 이유다. 가짜는 시험과 하나([0005](0005-시험-가짜-백엔드-하나를-공유.md))라 계약 타입과 어긋나면 tsc 가 막는다. `src` 와 운영 빌드는 그대로다(`dist` 에 MSW 없음, `sw.js` 는 그대로 실림, 2026-11-26 확인).

## 결과
- 얻는 것: `npm ci && npm run dev` 만으로 모든 화면을 눌러 볼 수 있다. 새로 고침하면 가짜 상태가 처음으로 돌아간다.
- 감수하는 것: 이 모드에서는 웹 푸시 서비스 워커(`public/sw.js`)를 서빙하지 않는다. 한 범위(`/console/`)에는 서비스 워커가 하나만 등록되어 MSW 워커와 함께 둘 수 없다. 웹 푸시는 단위 시험(`tests/unit/sw.test.ts`)과 배포 통합에서 본다. 알림 스트림 가짜는 이벤트 하나를 주고 끝나므로 화면이 다시 연결을 시도하는 것이 보인다.
