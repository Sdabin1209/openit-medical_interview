# 0005. 시험: 가짜 백엔드 하나를 Vitest 와 Playwright 가 공유

## 상태
승인(2026-11-10, 영역 작업자)

## 맥락
survey-service, model-runtime, oauth2-proxy 없이 혼자 시험해야 한다(워크스페이스 규칙, ADR 0012). 단위·계약·브라우저 시험이 같은 서버 동작을 가정해야 한다.

## 결정
`tests/fakes/backend.ts` 하나가 세 서버를 메모리로 흉내 낸다. 응답은 계약 생성 타입(`satisfies`)으로 만든다. Vitest 는 전역 `fetch` 자리에 끼우고, Playwright 는 `page.route` 로 연결한다. 가짜는 계약의 역할 요구에 따라 403 도 낸다. 제품 코드에는 시험용 문이 없다.

## 왜
타입이 같은 계약에서 나오므로 가짜가 계약과 어긋나면 `tsc` 가 막는다(실제로 필수 칸 누락 둘을 잡았다). 한 파일이라 시험들이 서로 다른 가정을 하지 않는다.

## 검토한 대안과 버리는 이유
- **MSW:** 표준 도구지만 의존이 늘고, ADR 0012 가 Playwright 는 `page.route` 로 정했다. 같은 가짜를 두 곳에 쓰려면 직접 만든 어댑터가 더 단순했다.
- **시험마다 응답을 손으로 적기:** 서버 동작이 시험마다 달라진다.

## 결과
- **얻는 것:** 타입으로 계약 정합성을 잡는다.
- **감수하는 것:** 가짜 응답은 JSON Schema 검증기로 검사하지 않는다(타입 수준만). `pattern`·`maxLength` 같은 값 제약은 가짜가 지키는지 보증하지 않는다. 실제 서버와의 적합성은 각 서비스 영역의 Schemathesis 가 본다. SSE 는 `page.route` 가 열린 채로 둘 수 없어 이벤트 하나를 주고 끝나는 스트림이고, 연결 유지·재연결은 단위 시험(가짜 EventSource)이 본다.

## 되돌리는 조건
가짜가 서버와 어긋나는 일이 반복되면 계약 스키마 검증기를 가짜에 붙이는 새 ADR.
