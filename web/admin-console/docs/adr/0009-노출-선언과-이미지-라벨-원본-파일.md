# 0009. 노출 선언(exposure.json)과 이미지 라벨의 원본 파일

## 상태
(경로 접두어는 ADR 0010 이 `/` 에서 바꿨다.) 승인(2026-11-11, 영역 작업자). 변경 요청 admin-console-005 의 처리(계약 README 9.0.0 '브라우저의 한 출처').

## 맥락
브라우저는 admin-console 의 한 출처만 안다. `/v1/` 를 survey-service 와 model-runtime 으로 나누는 일, 로그인 앞단, 알림 스트림의 시간 제한은 입구의 일이다. 입구는 각 서비스가 선언한 `Exposure` 를 합친다. 화면 이미지도 `io.openit.exposure`·`io.openit.inputs` 라벨이 필요하다.

## 결정
- 영역 폴더에 `exposure.json`(`Exposure`: 경로 접두어 `/`, 메서드 GET, 대상 `HUMAN_OIDC`, `egress` 없음)과 `inputs.json`(`ContainerInputs`: 실행 사용자 101, 환경 입력 없음, 쓰는 경로 `/tmp`(비영속), 시작 명령 nginx 기본 진입점)을 둔다. 이 둘이 라벨의 원본이다.
- `Dockerfile` 은 `ARG EXPOSURE`·`ARG INPUTS` 를 받아 라벨로 단다. 파일 내용을 Dockerfile 에 복사하지 않는다. 한 줄 JSON 으로 만들어 인자로 넘기는 일은 deploy build 의 몫이다. `JOBS` 는 없다(화면에 잡이 없다).
- `tests/contract/declarations.test.ts` 가 두 파일이 계약 스키마(`Exposure`, `ContainerInputs`)를 지키는지, Dockerfile 의 실행 사용자·시작 명령과 같은지, Dockerfile 이 ARG 로 라벨을 다는지 본다.

## 왜
- 입구가 읽는 것은 서비스가 선언한 `Exposure` 이고 서비스가 `/v1/` 의 자기 몫을 선언하므로(계약 README), 화면은 자기 경로(정적 파일)만 선언한다. 화면은 상대 경로만 안다(ADR 0002).
- 원본을 JSON 파일 하나로 두고 라벨은 인자로 달면 같은 사실이 두 곳에 있지 않다.
- 화면의 `/healthz`·`/readyz` 는 입구가 내보내지 않는 상태 경로라 선언하지 않는다(계약 README, 입구의 경로와 역할).

## 검토한 대안과 버리는 이유
- **화면이 두 서비스의 `/v1/` 도 선언:** 각 서비스가 자기 경로를 선언한다는 계약과 어긋나고 겹치면 입구가 시작하지 않는다.
- **Dockerfile 에 JSON 을 `LABEL` 로 직접 적기:** 원본과 두 곳이 된다.

## 결과
- **얻는 것:** 선언이 계약 스키마로 검증된다. 이미지 라벨은 빌드 인자로 채워진다.
- **감수하는 것:** 이 작업은 이미지를 빌드하지 않았다(deploy 의 일). 입구가 이 선언으로 라우트를 만드는지, `/` 가 정적 화면으로 가는지는 확인하지 못했다.

## 되돌리는 조건
계약의 `Exposure` 모양이 바뀌면 파일과 시험을 맞춘다.
